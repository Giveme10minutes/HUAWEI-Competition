# 方向路线：网络安全（Security）

资料ID：RM-P01-SEC ｜ 批次：RM-P01 ｜ 版本 v0.1 ｜ 整理日期：2026-11-03
性质：学习内容编排，不是岗位要求

## 1. 方向定位

网络安全负责发现并降低系统被攻击的风险，覆盖防御、检测、响应与合规。工作是**在授权范围内**理解攻击面、验证风险、加固系统、建立发现与处置流程。

日常主要处理的问题：漏洞与配置风险、身份与权限、日志与告警、应急响应、合规要求、供应链风险。

**边界提醒**：所有测试必须在明确授权范围内进行；本卡不提供任何绕过访问限制、未授权测试或规避平台风控的方法。

## 2. 阶段路线

### 阶段 1：基础

目标：能解释常见攻击为什么能成功。

主题顺序：

1. 网络基础：TCP/IP、HTTP、DNS、代理
2. 操作系统与权限模型
3. Web 基础：请求、会话、同源策略
4. 密码学常识：哈希、对称/非对称加密、证书
5. 安全模型：认证、授权、最小权限、纵深防御

阶段产出：一份“某类攻击的完整链路”说明（原理层面，不含可执行攻击步骤）。

### 阶段 2：漏洞与攻防

目标：能识别常见漏洞类型并写出修复建议。

主题顺序：

1. 常见 Web 漏洞类型与成因（注入、跨站脚本、跨站请求伪造、越权、文件上传）
2. 身份与会话安全
3. 依赖与供应链风险
4. 授权范围内的测试流程与报告写法
5. 漏洞分级与修复优先级

阶段产出：在授权靶场完成的漏洞报告（含成因、影响、修复建议）。

### 阶段 3：防御与加固

目标：能把安全要求落到系统与代码里。

主题顺序：

1. 系统与中间件加固
2. 身份与访问管理
3. 加密与密钥管理
4. 安全编码与代码审计基础
5. 日志规范与敏感信息脱敏
6. 备份与恢复

阶段产出：一份加固清单 + 一次代码审计记录。

### 阶段 4：检测与响应

目标：能发现异常并走完一次应急流程。

主题顺序：

1. 日志采集与集中管理
2. 检测规则与告警降噪
3. 事件分级与应急流程
4. 取证与溯源基础
5. 复盘与改进项跟踪

阶段产出：一条检测规则 + 一次桌面演练记录。

### 阶段 5：专项（按需选）

目标：深入某个安全域。

主题顺序（任选）：

1. 云安全与容器安全
2. 应用安全与 DevSecOps
3. 红蓝对抗与攻防演练
4. 数据安全与隐私合规
5. 工控/物联网安全

阶段产出：专项方案与验证结果。

## 3. 主题索引（检索用）

- 基础：TCP/IP、HTTP、TLS、证书（certificate）、哈希（hash）、加密（encryption）、认证（authentication）、授权（authorization）
- 漏洞：注入（injection）、XSS、CSRF、越权（access control）、文件上传（file upload）、供应链（supply chain）、CVE
- 防御：加固（hardening）、IAM、密钥管理（key management）、安全编码（secure coding）、审计（code audit）、脱敏（masking）
- 检测响应：SIEM、日志（logging）、告警（alerting）、应急（incident response）、取证（forensics）、复盘（postmortem）
- 专项：云安全（cloud security）、容器安全、DevSecOps、红蓝对抗（red/blue team）、合规（compliance）

## 4. 与相邻方向的边界

- **与运维**：运维保证可用性，安全保证不被攻破；加固、权限、日志是交集。
- **与后端**：后端写业务代码，安全提供安全编码规范、审计与漏洞修复建议。
- **与测试**：功能测试判断“能不能用”，安全测试判断“能不能被滥用”。

## 5. 本卡不包含

- 任何未授权测试、绕过访问限制、规避风控的操作方法；
- 具体漏洞利用代码；
- 具体法规条文的适用结论（应按官方文本与专业意见核对）；
- 学时、薪资、就业前景。
