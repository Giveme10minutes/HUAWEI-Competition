# 方向路线：测试与质量（QA）

资料ID：RM-P01-QA ｜ 批次：RM-P01 ｜ 版本 v0.1 ｜ 整理日期：2026-11-03
性质：学习内容编排，不是岗位要求

## 1. 方向定位

测试与质量负责用系统性方法发现缺陷、判断发布风险、推动质量改进。工作不是“点点点”，而是**设计能暴露问题的用例、把重复验证自动化、用数据说明质量状况**。

日常主要处理的问题：需求歧义、用例覆盖、自动化稳定性、回归成本、性能与兼容性、发布把关与线上问题复盘。

## 2. 阶段路线

### 阶段 1：测试基础

目标：能针对一个功能设计出有效的测试用例。

主题顺序：

1. 测试类型：功能、接口、性能、兼容、安全（概览）
2. 用例设计：等价类、边界值、场景法、状态迁移
3. 缺陷生命周期与缺陷报告写法
4. 需求评审与可测性
5. 测试环境与数据准备

阶段产出：一份功能测试用例集 + 一份可复现的缺陷报告。

### 阶段 2：接口与自动化

目标：能把核心回归变成自动化脚本。

主题顺序：

1. HTTP 与接口文档
2. 接口测试：参数、断言、数据驱动
3. 自动化框架与分层（用例、步骤、数据）
4. 测试数据管理与清理
5. 失败分析与误报治理
6. 版本控制与代码规范

阶段产出：一套可重复运行的接口自动化用例 + 运行报告。

### 阶段 3：UI 自动化与持续集成

目标：让自动化进入每次提交的流程。

主题顺序：

1. 元素定位与页面对象模式
2. 等待与稳定性处理
3. 端到端场景设计
4. 与持续集成/持续部署集成
5. 测试报告与失败通知
6. 并行执行与环境隔离

阶段产出：一条接入了自动化回归的流水线。

### 阶段 4：专项测试

目标：能评估非功能质量。

主题顺序：

1. 性能测试：负载模型、指标、瓶颈定位
2. 兼容性测试：浏览器/设备/系统版本
3. 安全测试基础（授权范围内）
4. 弱网、异常与恢复测试
5. 可访问性测试

阶段产出：一份压测报告（含瓶颈与建议）。

### 阶段 5：质量体系

目标：能从流程上降低缺陷流入与回归成本。

主题顺序：

1. 质量度量：缺陷密度、逃逸率、覆盖率
2. 测试策略与分层比例
3. 发布准入与质量门禁
4. 缺陷根因分析与改进跟踪
5. 线上问题复盘与监控联动

阶段产出：一份质量报告与改进项清单。

## 3. 主题索引（检索用）

- 基础：用例（test case）、等价类（equivalence partitioning）、边界值（boundary value）、缺陷（defect）、回归（regression）
- 自动化：接口测试（API testing）、断言（assertion）、数据驱动（data-driven）、页面对象（page object）、端到端（E2E）
- 流程：持续集成（CI）、测试报告（test report）、并行（parallel）、环境隔离（environment isolation）
- 专项：性能（performance）、压测（load test）、兼容性（compatibility）、弱网（network throttling）、可访问性（accessibility）
- 体系：覆盖率（coverage）、逃逸率（escaped defects）、质量门禁（quality gate）、根因分析（root cause analysis）

## 4. 与相邻方向的边界

- **与开发**：开发写单元测试保证内部正确；测试设计跨模块场景、验证需求与发布风险。
- **与运维**：测试判断版本是否可发；运维判断发布后服务是否健康。
- **与安全**：安全测试关注可被滥用；功能测试关注是否符合预期。
