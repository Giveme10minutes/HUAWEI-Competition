# 方向路线：移动端（Mobile）

资料ID：RM-P01-MOB ｜ 批次：RM-P01 ｜ 版本 v0.1 ｜ 整理日期：2026-11-03
性质：学习内容编排，不是岗位要求

## 1. 方向定位

移动端负责手机 App 或跨端应用的开发：界面、平台能力调用、本地数据、网络请求、性能与发布。与前端相近的是“做界面”，不同的是要面对**平台生命周期、权限、设备资源与上架流程**。

日常主要处理的问题：页面与导航、状态管理、设备能力（相机/定位/推送）、离线与缓存、启动与流畅度、崩溃与兼容、发版与灰度。

## 2. 阶段路线

### 阶段 1：平台与语言基础

目标：能做出一个能跑在手机上的单页应用。

主题顺序：

1. 选平台与语言：Android（Kotlin）/ iOS（Swift）/ 跨端（Dart + Flutter）
2. 开发环境与模拟器/真机调试
3. 平台基础：应用生命周期、页面与组件、权限模型
4. 布局与常用控件
5. 资源管理与国际化基础

阶段产出：单页 App（列表 + 详情 + 设置页），能安装到真机。

### 阶段 2：交互与状态

目标：能做出完整的多页应用。

主题顺序：

1. 导航与路由
2. 状态管理（页面状态、共享状态）
3. 表单与输入校验
4. 列表与滚动性能
5. 动画与手势
6. 深色模式与适配

阶段产出：多页 App，含表单、列表、页面跳转与状态保持。

### 阶段 3：数据与网络

目标：能接入真实接口并处理弱网与离线。

主题顺序：

1. 网络请求与 JSON 解析
2. 本地存储（键值、数据库）
3. 缓存与离线策略
4. 登录态与 Token 管理
5. 图片加载与缓存
6. 错误提示与重试

阶段产出：接后端 API 的 App，断网时能给出合理状态。

### 阶段 4：工程与发布

目标：能产出可发布的版本。

主题顺序：

1. 构建配置与多环境
2. 签名与打包
3. 应用商店上架流程与审核要点
4. 性能：启动时间、内存、帧率、包体积
5. 崩溃监控与埋点
6. 灰度发布与版本兼容

阶段产出：可发布的安装包 + 崩溃监控接入 + 一次灰度方案。

### 阶段 5：专项（按需选）

目标：深入平台能力或跨端方案。

主题顺序（任选）：

1. 跨端框架（Flutter / React Native）深入
2. 音视频、地图、推送等平台能力
3. 原生与跨端混合开发
4. 性能专项（渲染、内存、耗电）
5. 组件化与模块化架构

阶段产出：一个专项作品与取舍说明。

## 3. 主题索引（检索用）

- 平台与语言：Android、Kotlin、iOS、Swift、Flutter、Dart、React Native
- 基础：生命周期（lifecycle）、组件（widget/view）、布局（layout）、权限（permission）、导航（navigation）
- 状态：状态管理（state management）、路由（routing）、表单（form）
- 数据：网络（HTTP）、JSON、本地存储（local storage）、SQLite、缓存（cache）、离线（offline）
- 工程：构建（build）、签名（signing）、上架（app store release）、性能（performance）、崩溃（crash）、埋点（analytics）、灰度（staged rollout）

## 4. 与相邻方向的边界

- **与前端**：概念相通（组件、状态、路由），但运行环境与平台能力不同；Web 的响应式不等于移动端适配。
- **与后端**：移动端消费接口，不承担业务规则与数据持久化。
- **与系统底层**：移动端在应用框架层开发，不涉及驱动、内核与硬件抽象。
- **与设计**：平台设计规范（导航、控件、手势）会直接影响实现方式。

## 5. 本卡不包含

- 游戏引擎与游戏玩法开发；
- 具体商店的政策细节（会变化，应按官方文档核对）；
- 学时、薪资、就业前景；
- 设备厂商定制系统的差异清单。
