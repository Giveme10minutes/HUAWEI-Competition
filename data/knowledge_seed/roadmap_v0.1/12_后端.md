# 方向路线：后端（Backend）

资料ID：RM-P01-BE ｜ 批次：RM-P01 ｜ 版本 v0.1 ｜ 整理日期：2026-11-03
性质：学习内容编排，不是岗位要求

## 1. 方向定位

后端负责服务端的业务规则、数据存取与对外接口：接收请求、校验、处理业务、读写数据库、返回结果，并保证在并发和故障下仍然正确、可恢复。

日常主要处理的问题：接口设计、数据库与事务、并发与资源、鉴权与越权、错误处理、缓存、稳定性与容量。

## 2. 阶段路线

### 阶段 1：语言与运行时

目标：能用一门语言写服务端程序，理解请求如何被处理。

主题顺序：

1. 选一门语言（Java / Python / Go / Node.js 均可）的语法与标准库
2. 包管理与依赖
3. 异常与错误处理
4. 文件与进程基础
5. 简单 HTTP 服务（路由、请求、响应）
6. 调试与日志

阶段产出：一个提供少量接口的单体服务，能启动、能看日志、能处理报错。

### 阶段 2：数据与接口

目标：能设计并实现一套可用的 CRUD 接口。

主题顺序：

1. SQL：查询、连接、聚合
2. 数据建模：表设计、主外键、范式与反范式
3. 索引与执行计划
4. 事务与隔离级别
5. ORM 或数据库驱动
6. REST 接口设计：资源、方法、状态码、分页
7. 参数校验与统一错误返回
8. 鉴权基础：会话、Token、权限模型

阶段产出：带数据库的 CRUD 服务 + 接口文档，能处理非法输入。

### 阶段 3：工程化

目标：把服务做成可测试、可部署、可维护的工程。

主题顺序：

1. 分层与依赖组织（接口层、业务层、数据层）
2. 配置与环境管理
3. 缓存（本地缓存、Redis）与失效策略
4. 消息队列基础（异步、解耦、重试）
5. 并发模型（线程池、协程、异步 IO）
6. 单元测试与接口集成测试
7. 容器化打包与部署

阶段产出：可测试的服务 + 容器镜像 + 部署说明。

### 阶段 4：稳定性与规模

目标：能在流量上升和局部故障时保持服务可用。

主题顺序：

1. 服务拆分与网关
2. 限流、熔断、重试与超时
3. 可观测性：日志、指标、链路追踪
4. 幂等、去重与最终一致性
5. 安全问题：注入、越权、敏感信息、密钥管理
6. 容量评估与压测
7. 故障演练与降级方案

阶段产出：压测报告 + 一次故障演练记录（含降级与恢复步骤）。

### 阶段 5：专项（按需选）

目标：深入某个技术域。

主题顺序（任选）：

1. 高并发与性能调优
2. 存储引擎与检索
3. 消息与流处理
4. 搜索与推荐服务
5. 多租户与权限系统
6. 服务网格与云原生部署

阶段产出：一个可复现的专项方案与验证结果。

## 3. 主题索引（检索用）

- 语言与运行时：Java、Python、Go、Node.js、JVM、协程（coroutine）、线程池（thread pool）
- 数据：SQL、索引（index）、事务（transaction）、隔离级别（isolation）、ORM、Redis、缓存（cache）、消息队列（message queue）、Kafka
- 接口：REST、HTTP、状态码（status code）、分页（pagination）、鉴权（authentication）、JWT、权限（authorization）
- 工程：分层（layering）、配置（configuration）、测试（unit/integration test）、容器（Docker）、CI/CD
- 稳定：网关（gateway）、限流（rate limiting）、熔断（circuit breaker）、重试（retry）、可观测性（observability）、链路追踪（tracing）、幂等（idempotency）、压测（load testing）
- 安全：注入（injection）、越权（broken access control）、密钥管理（secret management）

## 4. 与相邻方向的边界

- **与前端**：后端不对“界面长什么样”负责，但要对接口契约、数据正确性和权限负责。
- **与运维**：后端关注应用逻辑与资源使用，运维关注运行环境、发布与故障恢复；小团队里两者常由同一人承担。
- **与数据**：后端面向在线业务库（事务、低延迟），数据方向面向分析与离线管道（批量、口径、数仓）。
- **与系统底层**：后端在应用层解决问题，底层方向关心内存、协议与性能极限。
