# 方向路线：云与运维（DevOps / SRE）

资料ID：RM-P01-OPS ｜ 批次：RM-P01 ｜ 版本 v0.1 ｜ 整理日期：2026-11-03
性质：学习内容编排，不是岗位要求

## 1. 方向定位

云与运维负责让服务“能被部署、能稳定运行、出故障能恢复、成本可控”。核心是**把交付与运行环境做成可重复、可观测、可自动化的过程**，而不是手工登录服务器改配置。

日常主要处理的问题：环境不一致、发布回滚、监控告警、容量与成本、故障定位与恢复、权限与密钥。

## 2. 阶段路线

### 阶段 1：系统与网络基础

目标：能独立登录服务器排查基本问题。

主题顺序：

1. Linux：目录与权限、进程、服务管理、包管理
2. Shell 脚本与文本处理
3. 网络基础：IP、端口、DNS、HTTP、路由
4. 日志查看与故障初判
5. 编辑器与远程工作方式（SSH、文件传输）

阶段产出：一份常用排障命令清单 + 一次真实故障的定位记录。

### 阶段 2：交付流水线

目标：把“提交代码到部署”变成自动过程。

主题顺序：

1. Git 分支与版本策略
2. 构建与制品管理
3. 持续集成：自动测试、静态检查
4. 持续部署：环境、审批、回滚
5. 配置与密钥管理（不入库）

阶段产出：一条从提交到部署的流水线 + 回滚演练。

### 阶段 3：容器与编排

目标：能用容器方式部署多服务应用。

主题顺序：

1. 容器基础：镜像、层、网络、数据卷
2. 镜像构建与最小化
3. 编排基础：工作负载、服务发现、配置与密钥
4. 存储与有状态服务
5. 滚动更新与健康检查

阶段产出：一套多服务容器化部署 + 更新与回滚记录。

### 阶段 4：云资源与基础设施即代码

目标：能用代码描述环境，减少手工操作。

主题顺序：

1. 云计算基本模型：计算、存储、网络
2. 负载均衡与对象存储
3. 身份与权限（最小权限）
4. 基础设施即代码（声明式配置、状态管理）
5. 环境隔离与成本标签

阶段产出：用代码创建一套可复现的环境。

### 阶段 5：可靠性与成本

目标：能定义并守住服务的可靠性目标。

主题顺序：

1. SLI/SLO 与错误预算
2. 监控、告警与值班
3. 日志与链路追踪
4. 容量规划与压测
5. 故障演练与复盘
6. 成本分析与优化

阶段产出：一份 SLO 与告警规则 + 一次演练复盘报告。

## 3. 主题索引（检索用）

- 系统：Linux、Shell、进程（process）、权限（permission）、包管理（package manager）
- 网络：TCP/IP、DNS、HTTP、负载均衡（load balancing）、CDN
- 交付：CI/CD、流水线（pipeline）、制品（artifact）、回滚（rollback）、Git
- 容器：Docker、镜像（image）、Kubernetes、编排（orchestration）、服务发现（service discovery）
- 云与 IaC：云主机（compute）、对象存储（object storage）、IAM、Terraform、声明式（declarative）
- 可靠性：SLO、监控（monitoring）、告警（alerting）、日志（logging）、追踪（tracing）、容量（capacity）、演练（chaos/game day）、成本（cost）

## 4. 与相邻方向的边界

- **与后端**：后端负责应用逻辑与资源使用；运维负责运行环境、发布与恢复。两者在“可观测性”和“部署”上有大量交集。
- **与安全**：安全负责策略与检测；运维负责把加固措施落到环境与权限上。
- **与测试**：测试判断功能是否正确；运维判断服务是否健康、变更是否安全。
