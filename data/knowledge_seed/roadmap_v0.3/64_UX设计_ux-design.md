# UX 设计：围绕用户任务设计交互与体验

UX 设计关注用户在使用产品完成目标时的整体感受，包括是否找得到入口、步骤是否顺畅、出错后能否恢复。它依靠研究与观察判断设计是否有效，而不是只凭界面是否好看。

来源：定位说明为整理者编写；主题名称取自 roadmap.sh 的 UX 设计路线索引（https://roadmap.sh/ux-design）；用途说明为整理者归纳。

## UX 设计是什么：范围与产出

UX 设计覆盖从理解用户到验证方案的多个环节，产出可能是研究报告、流程图、线框图和可用性测试记录。它与视觉设计有交集，但关注点更多在交互逻辑与任务完成。

来源：主题名称取自 roadmap.sh 的 UX 设计路线索引（https://roadmap.sh/ux-design）；范围说明为整理者归纳。

## UX 设计的用户研究与需求理解

研究的目的不是证明已有想法，而是发现用户在真实场景中的做法与困难。小样本访谈配合观察，通常比大范围问卷更能解释为什么。

相关方法（6 项）：用户访谈（了解动机与困难）、现场观察（看真实使用环境）、问卷调查（收集分布信息）、可用性测试（观察操作过程）、人物角色（概括典型用户）、用户旅程图（梳理体验阶段）。

来源：主题名称取自 roadmap.sh 的 UX 设计路线索引（https://roadmap.sh/ux-design）；研究方法说明为整理者归纳。

## UX 设计的交互设计与信息架构

信息架构决定内容如何分类与命名，交互设计决定用户如何一步步完成任务。设计时要把空状态、加载、错误和权限不足等状态一起画出，而不是只画理想路径。

相关产出（6 项）：站点地图（内容层级）、用户流程（任务步骤）、线框图（页面布局）、可交互原型（模拟操作）、状态清单（各种边界状态）、交互说明（规则与反馈）。

来源：主题名称取自 roadmap.sh 的 UX 设计路线索引（https://roadmap.sh/ux-design）；交互设计说明为整理者归纳。

## UX 设计的可用性评估与迭代

可用性评估通过观察真实用户完成任务来发现问题，常见观察点包括能否完成、耗时与出错位置。发现问题后应优先修改影响任务完成的环节，而不是只调整视觉。

来源：主题名称取自 roadmap.sh 的 UX 设计路线索引（https://roadmap.sh/ux-design）；评估说明为整理者归纳。

## UX 设计与产品设计、设计系统的区别

UX 设计聚焦用户完成任务的交互过程与体验质量；产品设计决定做哪些功能与整体流程；设计系统提供统一的组件与规范。三者目标不同，实际项目中常需要协同。

来源：三者区别为整理者归纳；主题名称取自 roadmap.sh 的 UX 设计路线索引（https://roadmap.sh/ux-design）。

## 如何练习 UX 设计

一个可操作的小目标是：选一个常用的校园服务页面，请三位同学完成同一任务并记录卡住的位置，再画出改进后的流程与线框图。用同样的任务再测一次，对比完成情况。
