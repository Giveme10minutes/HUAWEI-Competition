# Codex：在终端中运行的代码生成助手

Codex 是 OpenAI 的编程助手，以命令行工具为主要形态，也可以结合网页端使用。它按自然语言指令读取项目代码、修改文件并执行命令，属于“在终端里工作的编码代理”这一类工具。

来源：主题名称取自 roadmap.sh 的 Codex 路线索引（https://roadmap.sh/codex）；参考 Codex CLI 开源仓库（https://github.com/openai/codex）。

## Codex 是什么：终端里的编码代理

Codex CLI 的仓库简介写明它是“在终端中运行的轻量编码代理”。启动后它在当前项目目录中工作，可以搜索文件、生成补丁、运行测试，并把结果反馈给用户，由用户决定是否采纳。

参考：Codex CLI 开源仓库（https://github.com/openai/codex）。

## Codex 的常见工作流

典型流程是：描述目标、让助手查看相关文件、审阅它提出的改动、批准执行命令，最后检查差异并提交。把任务拆小、在每一步确认，比一次给出模糊的大任务更容易得到可用结果。

相关环节（5 项）：读取代码（定位相关文件）、提出改动（生成补丁）、执行命令（运行测试与构建）、审阅差异（检查改动内容）、提交（保存结果）。

来源：主题名称取自 roadmap.sh 的 Codex 路线索引（https://roadmap.sh/codex）；流程为整理者归纳。

## Codex 的配置与项目约定

Codex 使用项目内的说明文件记录构建命令、代码风格与约束，也用配置文件保存模型和审批等设置。明确哪些命令可以自动执行、哪些需要确认，是使用前的必要准备。

相关概念（5 项）：项目说明文件（记录项目约定）、配置文件（保存运行设置）、审批策略（控制命令执行）、沙箱模式（限制文件与网络访问）、会话（连续的任务上下文）。

来源：主题名称取自 roadmap.sh 的 Codex 路线索引（https://roadmap.sh/codex）；概念说明为整理者归纳。

## Codex 与其他编程助手的关系

Codex 与终端里的其他 AI 编程助手形态接近：都在项目目录中读写文件、执行命令，差别主要在支持的平台、配置方式和集成范围。选择时可按自己常用的编辑器、终端和协作流程判断，不必追求同时使用多个。

来源：定位说明为整理者编写；比较为整理者归纳。

## 如何开始练习 Codex

在一个带有测试的小项目里，让助手完成一次“修复失败测试”的任务：先复现失败，再修改代码并运行测试确认通过。产出是一次通过的测试运行和一份可审查的代码差异。

来源：定位说明为整理者编写；练习设计为整理者归纳。
