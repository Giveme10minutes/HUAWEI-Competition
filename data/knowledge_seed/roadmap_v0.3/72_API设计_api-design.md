# API 设计：设计稳定、可演进的接口契约

API 设计是决定接口对外暴露什么、如何调用以及如何随需求变化而演进的工作。好的接口让调用方容易理解和使用，也让提供方能在不破坏既有调用的情况下增加能力。

来源：定位说明为整理者编写；主题名称取自 roadmap.sh 的 API 设计路线索引（https://roadmap.sh/api-design）；用途说明为整理者归纳。

## API 设计是什么：契约与兼容性

接口一旦被外部使用，就形成事实上的契约，修改字段或语义可能让调用方出错。设计时需要区分哪些变化是兼容的，例如新增可选字段，哪些会破坏调用方。

来源：主题名称取自 roadmap.sh 的 API 设计路线索引（https://roadmap.sh/api-design）；契约说明为整理者归纳。

## API 设计的核心内容：资源、方法与状态

以 HTTP 接口为例，设计要确定资源如何命名、用哪些方法表达操作、返回什么状态码与错误结构。分页、过滤和排序也应提前约定，避免每个接口各写一套。

相关主题（6 项）：资源命名（用名词表示对象）、HTTP 方法（表达操作语义）、状态码（表示结果类别）、错误结构（统一错误信息）、分页（控制返回数量）、版本策略（管理不兼容变更）。

来源：主题名称取自 roadmap.sh 的 API 设计路线索引（https://roadmap.sh/api-design）；核心内容说明为整理者归纳。

## API 的鉴权与安全考虑

接口需要确认调用者身份并限制其能做的操作，常见方式包括密钥、令牌和基于角色的授权。输入校验、限流和审计日志也应作为接口设计的一部分，而不是上线后再补。

相关主题（6 项）：API 密钥（识别调用方）、访问令牌（授权访问范围）、基于角色的授权（按角色放行）、输入校验（拒绝非法参数）、限流（控制调用频率）、审计日志（记录敏感操作）。

来源：主题名称取自 roadmap.sh 的 API 设计路线索引（https://roadmap.sh/api-design）；安全说明为整理者归纳。

## API 的文档与测试

文档应让调用方不读源码就能发起请求，测试应覆盖正常路径和错误路径。契约测试可以在接口变更时提前发现与调用方约定不一致的地方。

相关实践（5 项）：接口描述文件（机器可读的定义）、示例请求（可直接复制调用）、错误示例（说明失败返回）、契约测试（校验调用约定）、模拟服务（在实现前联调）。

来源：主题名称取自 roadmap.sh 的 API 设计路线索引（https://roadmap.sh/api-design）；文档与测试说明为整理者归纳。

## 如何练习 API 设计

一个可操作的小目标是：为一个图书借阅场景设计三个接口，写出路径、参数、成功与失败返回，并用接口描述文件保存。再让同学只看文档发起一次请求，记录他需要追问的地方。
