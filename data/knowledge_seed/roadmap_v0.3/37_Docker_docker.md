# Docker：容器化应用与运行环境

Docker 把应用及其依赖打包成镜像，并以容器方式运行。镜像提供一致的运行环境，容器之间相互隔离，因此同一份构建结果可以在开发机、测试环境和服务器上以相近方式启动。

## Docker 是什么：解决什么问题

“在我机器上能跑”的问题常来自依赖版本、系统库和配置差异。Docker 把应用、运行时和依赖固化到镜像中，运行时再挂载配置与数据，从而减少环境差异；容器共享宿主内核，启动比虚拟机轻量。

参考：Docker 官方文档（https://docs.docker.com/）。

## Docker 的核心概念：镜像、容器与仓库

镜像是只读模板，容器是镜像的运行实例，仓库用于存放和分发镜像。容器内的文件系统改动默认随容器删除而消失，需要保留的数据应放在卷或绑定挂载中。

相关概念（6 项）：镜像（只读的应用模板）、容器（镜像的运行实例）、Dockerfile（构建镜像的说明文件）、仓库（镜像的分发位置）、卷（由 Docker 管理的数据存储）、绑定挂载（把宿主机目录挂进容器）。

参考：Docker 官方文档（https://docs.docker.com/）。

## Docker 的镜像构建：Dockerfile 与分层

Dockerfile 按顺序描述构建步骤，每条指令生成一层，未变化的层可以复用缓存。把变化少的依赖安装放在前面、把源码复制放在后面，通常能减少重复构建的时间。

相关指令（6 项）：FROM（指定基础镜像）、RUN（构建时执行命令）、COPY（复制文件进镜像）、WORKDIR（设置工作目录）、EXPOSE（声明服务端口）、CMD（容器启动命令）。

参考：Docker 官方文档（https://docs.docker.com/）。

## Docker 的网络与数据管理

容器默认使用桥接网络，可以通过端口映射让宿主机访问容器服务，也可以让多个容器加入同一自定义网络后按名称互相访问。数据持久化则有卷和绑定挂载两种常见方式。

相关操作（5 项）：端口映射（暴露容器服务）、自定义网络（容器间按名称通信）、卷（持久化数据）、绑定挂载（直接使用宿主目录）、数据卷备份（导出与恢复容器数据）。

来源：主题名称取自 roadmap.sh 的 Docker 路线索引（https://roadmap.sh/docker）；说明为整理者归纳。

## Docker Compose：多容器应用的组织

一个应用常由 Web 服务、数据库和缓存等多个容器组成，逐个启动和连接很繁琐。Compose 用一份声明文件描述服务、网络和卷，通过一条命令统一启动和停止。

相关概念（5 项）：服务（一个容器定义）、项目（一组相关服务）、Compose 文件（声明式配置）、依赖关系（控制启动顺序）、覆盖文件（按环境覆盖配置）。

参考：Docker Compose 文档（https://docs.docker.com/compose/）。

## 如何开始练习 Docker

最小练习是为一个返回固定文本的小型 Web 应用写 Dockerfile，构建镜像并运行容器，通过端口映射访问；再加入卷保存数据，最后用 Compose 同时启动应用与数据库。产出是 Dockerfile、Compose 文件和一份启动命令说明。
