# Shell 与 Bash：命令行脚本与自动化

Shell 是接收命令并交给操作系统执行的程序接口，Bash 是其中使用广泛的一种实现，常见于 Linux 和 macOS 的命令行环境。把重复的手工命令写成脚本，可以完成文件处理、程序启动、环境准备和定时任务。

来源：定位说明为整理者编写；主题名称取自 roadmap.sh 的 Shell 与 Bash 路线索引（https://roadmap.sh/shell-bash）。

## Bash 脚本的结构、变量与参数

脚本通常以解释器声明开头，按顺序执行命令；变量赋值等号两侧不能有空格，引用变量时加双引号可以避免空格被拆成多个参数。脚本参数通过位置变量读取，上一条命令的退出状态保存在 `$?` 中，可供后续判断。

相关概念（6 项）：解释器声明（指定解释器）、位置参数（按序号读取脚本参数）、参数个数（统计传入参数数量）、退出状态（上一条命令的结果码）、环境变量（传递给子进程的配置）、命令替换（把命令输出嵌入字符串）。它们都是书写脚本时直接接触的语法元素。

来源：主题名称取自 roadmap.sh 的 Shell 与 Bash 路线索引（https://roadmap.sh/shell-bash）；用途说明为整理者归纳。

## Bash 的条件、循环与函数

Bash 用 if、case 和 test 类命令做分支判断，用 for、while 遍历列表或按条件重复执行。函数把一段命令封装起来，配合局部变量和返回值，可以减少重复并让脚本结构更清楚。

相关概念（6 项）：if 条件（按命令退出状态分支）、case 分支（按模式匹配选择）、for 循环（遍历列表）、while 循环（条件为真时重复）、函数（封装可复用命令块）、局部变量（限制在函数内的变量）。这些是控制流程与代码组织的语法。

## Shell 的管道、重定向与文本处理

管道把前一个命令的标准输出接到后一个命令的标准输入，重定向把输出写入文件或从文件读取，两者组合后可以用短命令完成筛选、统计和格式转换。处理文本时通常先过滤再计数，最后排序查看结果。

相关命令（7 项）：管道（连接命令的输入输出）、输出重定向（写入或追加到文件）、错误重定向（单独收集错误信息）、Here 文档（把多行文本作为输入）、grep（按模式筛选行）、awk（按列处理与统计）、cut（截取指定字段）。它们是命令或语法机制，不是独立的编程语言。

## Shell 的文件、权限与进程管理

脚本经常需要创建目录、复制或删除文件，并确认执行者是否具备相应权限；权限分为读、写、执行，分别对属主、属组和其他用户设置。进程管理则关注任务在后台运行、查看状态以及定时触发。

相关命令（9 项）：chmod（修改文件权限）、chown（修改文件属主）、mkdir（创建目录）、cp（复制文件）、mv（移动文件）、rm（删除文件）、ps（查看进程状态）、jobs（查看会话后台任务）、cron（按计划执行任务）。

这些命令覆盖文件操作、权限、进程查看与定时执行。

## Shell 脚本的调试与可靠性

脚本出错时往往先表现为某条命令失败却继续执行，因此需要主动检查语法、打开执行跟踪并设置失败即退出。对参数和文件路径先做存在性判断，可以避免误删或写入错误位置。

相关做法（5 项）：语法检查（不执行只检查语法）、执行跟踪（逐条打印实际运行的命令）、快速失败（命令失败时立即退出）、未定义变量检查（引用空变量时报错）、管道失败检查（管道中任一命令失败即报错）。这些是排查与加固脚本的习惯，不是软件。

## 如何开始练习 Shell

可以写一个备份脚本：接收一个目录作为参数，检查目录存在，用日期生成压缩包名称，把结果写入日志并在失败时返回非零状态。写完后故意传入不存在的路径，观察脚本如何报错，再用执行跟踪定位问题。
