# DevOps：方向定位与工作内容线索

DevOps 关注开发与运维之间的协作方式，把构建、测试、部署和运行监控做成可重复、可观测的过程；它更像实践与流程的集合，而不是某一件具体工具。这是学习路线视角的方向整理，不是某个具体岗位的招聘要求。

来源：定位说明为整理者编写；主题名称取自 roadmap.sh 的 DevOps 路线索引（https://roadmap.sh/devops）。

## DevOps 的工作内容与常见交付

这类工作通常包括维护代码与构建流程、编写自动化测试与部署脚本、管理环境配置与密钥、接入日志与监控，并处理发布中的异常。常见交付包括可重复的构建流水线、部署说明、监控面板和故障复盘记录。

来源：该方向的定位为“把交付与运行环境做成可重复、可观测、可自动化的过程”；展开为整理者归纳。

## DevOps 的学习内容：版本控制与持续集成

持续集成要求在每次提交后自动构建并运行检查，尽早暴露问题；持续交付进一步把可部署的产物准备好。学习时可以先为一个练习项目配置“提交后自动运行测试”的最小流水线。

相关工具与主题（6 项）：Git（版本控制）、GitHub Actions（托管流水线）、GitLab CI（流水线配置）、Jenkins（自动化服务器）、ArgoCD（声明式部署）、Artifactory（管理构建产物）。

来源：主题名称取自 roadmap.sh 的 DevOps 路线索引（https://roadmap.sh/devops）；用途说明为整理者归纳。

## DevOps 的学习内容：容器、编排与配置管理

容器把应用和依赖打成一个包，编排工具负责在多台机器上调度和伸缩，配置管理则用描述文件代替手工操作，让环境之间尽量一致。三者常配合使用，但各自解决的问题不同。

相关技术与工具（7 项）：Docker（构建与运行容器）、Kubernetes（容器编排）、Ansible（配置管理）、Helm（打包编排配置）、Prometheus（指标采集）、Grafana（监控面板）、OpenTelemetry（采集追踪数据）。

来源：主题名称取自 roadmap.sh 的 DevOps 路线索引（https://roadmap.sh/devops）；用途说明为整理者归纳，工具清单为整理者补充。

## DevOps 与云计算的区别

云计算更关注资源从哪里来、如何组织和隔离；DevOps 更关注变更如何被构建、测试、部署和观测。前者偏基础设施，后者偏交付流程，实际项目中两者配合出现，这里只是侧重上的区分。

来源：定位说明为整理者编写；比较为整理者归纳。

## 从零了解 DevOps 的学习顺序与实践

可以从一个练习项目开始：用 Git 管理代码，配置提交后自动运行测试，再把应用打包成容器并在本地启动。之后加入一条部署步骤和最基本的健康检查，记录每次失败的原因，逐步体会流程比单次手工操作可靠在哪里。

## 判断自己是否适合 DevOps 的观察线索

可以用几个可观察的线索自查：是否愿意把重复操作写成脚本，是否习惯从日志和监控里找线索，是否在意环境之间的一致性。这些只是帮助你判断是否愿意投入时间的观察点，不构成适配结论。
