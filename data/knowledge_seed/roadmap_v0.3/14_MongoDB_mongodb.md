# MongoDB：面向文档的数据库

MongoDB 是一个文档型 NoSQL 数据库，用类似 JSON 的 BSON 文档保存数据，字段可以嵌套对象和数组。它提供查询语言、二级索引、聚合管道与复制集，常用于结构灵活、读写量较大的应用。

来源：主题名称取自 roadmap.sh 的 MongoDB 路线索引（https://roadmap.sh/mongodb）；定位说明为整理者归纳。

## MongoDB 是什么：解决什么问题

关系型数据库通常要先定义表结构，字段调整需要迁移；MongoDB 允许同一集合中的文档拥有不同字段，适合结构经常变化或层级明显的数据。应用通过官方驱动以对象形式读写，不必先做对象与表结构的映射。

参考：MongoDB 官方手册（https://www.mongodb.com/docs/manual/）。

## MongoDB 的核心概念与常用操作

数据库由集合组成，集合存放文档，每个文档用 _id 作为唯一主键。插入、查询、更新和删除分别由 insert、find、update、delete 系列方法完成，聚合则通过管道串联多个阶段。

相关概念（6 项）：文档（BSON 格式的数据记录）、集合（文档的容器）、_id（文档唯一主键）、ObjectId（默认主键类型）、复制集（多节点数据冗余）、分片集群（按分片键水平扩展）。

参考：MongoDB 官方手册（https://www.mongodb.com/docs/manual/）。

## MongoDB 的查询与聚合管道

查询条件本身是一个文档，用比较、逻辑、数组和正则等操作符描述要匹配的字段。聚合管道按顺序执行各阶段，前一阶段的输出作为后一阶段的输入，可完成筛选、投影、分组和关联。

相关操作符（6 项）：$match（筛选文档）、$project（选择与计算字段）、$group（分组统计）、$lookup（关联其他集合）、$unwind（展开数组字段）、$sort（排序）。

参考：MongoDB 官方手册聚合部分（https://www.mongodb.com/docs/manual/aggregation/）。

## MongoDB 的索引与数据模型设计

索引让查询不必扫描整个集合，设计时应结合查询条件与排序字段。数据模型可以选择把相关数据嵌入同一文档，也可以用引用拆分到多个集合，取决于读取方式与更新频率。

相关索引类型（5 项）：单字段索引（加速单字段查询）、复合索引（匹配多字段过滤与排序）、唯一索引（阻止重复值）、TTL 索引（到期自动删除文档）、地理空间索引（按位置范围查询）。

参考：MongoDB 官方手册索引部分（https://www.mongodb.com/docs/manual/indexes/）。

## MongoDB 的典型使用场景

MongoDB 常用于字段不固定、读写频繁或数据带层级关系的场景，例如内容管理、商品目录、用户资料与事件日志。它支持多文档事务，但事务范围与性能取舍仍需按业务评估。

相关场景（5 项）：内容管理（结构多变的文章与评论）、商品目录（多规格嵌套属性）、用户资料（字段持续扩展）、事件日志（批量写入与范围查询）、地理数据（附近位置查询）。

## 如何开始练习 MongoDB

最小练习是启动本地实例，建立数据库与集合，插入 5 条以上含嵌套字段的文档，完成条件查询、数组查询和聚合分组各一次，再用 explain 检查查询是否命中索引。产出是一组可重复执行的命令和一份集合结构说明。
