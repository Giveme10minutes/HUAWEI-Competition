# Redis：内存中的数据结构存储

Redis 是一个把数据保存在内存中的键值存储系统，支持字符串、哈希、列表、集合、有序集合等结构。它提供过期、持久化、复制与集群能力，常被用作缓存、计数器和轻量消息通道。

来源：主题名称取自 roadmap.sh 的 Redis 路线索引（https://roadmap.sh/redis）；定位说明为整理者归纳。

## Redis 是什么：解决什么问题

把热点数据放在内存里可以减少对后端数据库的重复查询，Redis 因此常见于缓存场景。它同时提供原子操作和多种数据结构，使计数、排行榜、去重等需求不必只靠字符串键值实现。

参考：Redis 官方文档（https://redis.io/docs/latest/get-started/）。

## Redis 的核心数据结构与常用命令

Redis 的键对应一个值，值的类型决定可用的命令。字符串适合缓存和计数，哈希适合存对象字段，列表和集合分别处理顺序与去重，有序集合按分值排序，流用于追加式消息。

相关结构（6 项）：字符串（缓存与计数）、哈希（对象字段集合）、列表（有序可重复序列）、集合（无序去重集合）、有序集合（按分值排序）、流（追加式消息日志）。

参考：Redis 官方文档数据类型部分（https://redis.io/docs/latest/develop/data-types/）。

## Redis 的过期、淘汰与持久化

键可以设置过期时间，到期后自动删除；内存达到上限时，Redis 按配置的淘汰策略移除部分键。持久化有 RDB 快照与 AOF 日志两种方式，前者紧凑、后者记录更细，实际取舍取决于能否接受少量数据丢失。

相关机制（6 项）：EXPIRE（设置键的过期时间）、TTL（查看剩余存活时间）、淘汰策略（内存满时的移除规则）、RDB（定时快照持久化）、AOF（追加写命令日志）、混合持久化（快照与日志结合）。

参考：Redis 官方文档持久化部分（https://redis.io/docs/latest/operate/oss_and_stack/management/persistence/）。

## Redis 的高可用与扩展

单机 Redis 存在容量和故障单点问题。复制让从节点跟随主节点，Sentinel 负责监控与故障转移，Cluster 把数据分片到多个主节点，客户端按分片键路由请求。

相关组件（5 项）：主从复制（数据同步到从节点）、Sentinel（监控与自动故障转移）、Cluster（分片与多主扩展）、RedisInsight（图形化查看与管理）、redis-cli（命令行客户端）。

参考：Redis 官方文档（https://redis.io/docs/latest/）。

## Redis 的典型使用场景

Redis 适合读写频繁、能容忍内存容量限制的数据，例如页面缓存、会话、接口限流、排行榜和简单队列。涉及复杂查询或强事务的业务数据，通常仍放在关系型数据库中。

相关场景（5 项）：缓存（减少数据库查询）、会话存储（保存登录状态）、限流计数（按时间窗口计数）、排行榜（有序集合排序）、消息队列（列表或流传递任务）。

## 如何开始练习 Redis

最小练习是启动一个本地实例，用 redis-cli 写入字符串并设置过期时间，创建哈希保存对象、用列表做队列、用有序集合做排行榜，再用 INFO 查看内存与键数量。产出是一组命令和一个说明各结构用途的小结。
