# DevOps 入门：最小起步范围

DevOps 入门路线把完整的运维方向压缩成一个最小集合，目标是先跑通一次“改代码、自动检查、部署上线”的闭环。它不覆盖监控体系、集群编排与安全加固等完整内容。

来源：主题名称取自 roadmap.sh 的 DevOps 入门路线索引（https://roadmap.sh/devops-beginner）；用途说明为整理者归纳。

## DevOps 入门包含什么

入门阶段只需要理解三件事：代码存在哪里、改动如何被自动检查、结果怎样发布到一台机器上。对应到具体内容，是版本控制、一台可登录的 Linux 服务器、一个容器化的应用和一条自动化流程。

## DevOps 入门的最小起步内容：操作系统与版本控制

代码要有可回溯的历史，部署目标要能登录并执行命令。先在一台 Linux 机器上把应用手动跑起来，再考虑把这一步自动化。

相关基础（5 项）：Linux（服务器与命令行）、Git（记录代码变更）、GitHub（托管仓库）、SSH（远程登录）、网络基础（地址、端口与 DNS）。

## DevOps 入门的最小起步内容：容器、部署与自动化

容器把应用和依赖打包在一起，减少“本地能跑、服务器不行”的问题；自动化工具负责把代码变更送到服务器并重启服务。两者配合，才有可重复的发布过程。

相关工具（6 项）：Docker（打包与运行容器）、Nginx（反向代理与静态文件）、GitHub Actions（自动执行流程）、Ansible（批量配置服务器）、Terraform（声明式创建资源）、AWS（云主机与基础服务）。

来源：主题名称取自 roadmap.sh 的 DevOps 入门路线索引（https://roadmap.sh/devops-beginner）；用途说明为整理者归纳。

## DevOps 入门的最小起步内容：脚本与配置格式

自动化离不开脚本，选一门能快速写小工具的语言即可。入门路线列出的是可选语言，不是要求同时掌握；配置文件通常用 YAML 或 JSON 描述。

相关语言与格式（5 项）：Python（脚本与自动化）、Go（编写小型服务与工具）、Shell（串联系统命令）、YAML（描述配置与流水线）、JSON（交换配置与数据）。

## DevOps 入门的第一个可完成小目标

把一个简单网页应用放进容器，写好构建与运行命令，再用一条自动化流程在推送后重新部署到自己的服务器。产出是一个可访问的地址和一次由代码推送触发的部署记录。

入门路线省略了监控告警、日志体系、Kubernetes 编排、基础设施即代码的深入用法与安全加固。跑通闭环后，应回到完整方向补齐这些缺口，而不是把简化路线当作全部能力。
