# 后端学习路线（项目编排建议）

资料ID：`LP-P01-BE` ｜ 版本 v0.1 ｜ 整理日期：2026-11-03
性质：这是项目编排的学习建议，不是岗位要求、官方路线或就业承诺。阶段先后可按学生已有基础调整，不需要按固定周数完成。

## 1. 这个方向主要做什么

后端的主要交付物是“接口、业务规则与数据存取”。一个请求通常会经过：接收请求 → 校验参数 → 执行规则 → 读写数据 → 返回结果或错误；同时要保证并发和故障下仍然正确、可恢复。[RM-P01-MAP]

判断一段经历是不是后端工作，可以看三个信号：产出是否主要是接口、数据处理或服务；出问题是否先看服务日志、数据库状态和请求链路；失败代价是否包括数据错误、越权或服务不可用。后端不等于“必须会某门语言或某个框架”，语言和框架是可替换的工具。

## 2. 阶段路线

以下阶段是项目编排，不是 roadmap.sh 官方顺序，也不是行业统一标准。每个阶段都写清了进入条件，可以单独阅读。

### 阶段 1：跑通请求处理的最小闭环

- **进入条件**：已能用一门语言写基本程序（变量、函数、条件、循环、简单调试），不需要框架经验；没有语言基础时先补一门语言的基础，而不是同时学多门。
- **学习目标**：写一个能启动、能接收请求、能返回结果和错误的服务。
- **必要内容**：HTTP 请求与响应的基本结构；路由；读取路径参数、查询参数和请求体；参数校验；统一的错误返回；日志；用 curl 或接口工具发起请求。[SRC-BE-01][SRC-BE-02][SRC-BE-03]
- **可选或后置**：Web 框架、数据库、鉴权、容器。可以先用标准库或最小框架，但要知道框架替你做了什么。
- **最小实践产出**：一个有 2—3 个接口的小服务（例如健康检查、内存中的待办或计算接口），附启动说明和错误示例。
- **完成表现（可检查）**：正常请求、缺参数、参数类型错误、未知路由四类情况返回不同且合理的结果；日志能找到某次请求；错误响应不泄露堆栈；重启后能按说明再次启动。
- **卡住时缩小任务**：只做一个接口；先不做校验；用框架模板起步，但能逐行解释请求从进来到返回的路径。

### 阶段 2：数据持久化与增删改查

- **进入条件**：完成阶段 1，或已能写一个返回固定数据的接口；SQL 可以与本阶段同步学。
- **学习目标**：让数据在重启后仍然存在，接口能安全地读写数据库。
- **必要内容**：关系表与主键/外键；基础 SQL 的增删改查；参数化查询；事务的基本用法；索引的作用与代价；数据库连接配置；建表或迁移脚本。[SRC-BE-04]
- **可选或后置**：ORM、非关系数据库、缓存、分库分表。
- **最小实践产出**：一个待办或笔记的增删改查服务，数据存数据库，附建表脚本和少量初始数据。
- **完成表现（可检查）**：重启服务后数据仍在；查询不存在的 ID 返回明确的“未找到”；违反唯一约束时返回可理解的错误而不是崩溃；能演示一次事务回滚；拼接字符串的注入尝试无法生效。
- **卡住时缩小任务**：只做一张表；先只做新增和查询；用单机数据库文件，不搭服务器；不用 ORM，先写 SQL。

### 阶段 3：接口契约与协作

- **进入条件**：完成阶段 2，接口已经能读写真实数据。
- **学习目标**：让别人能按文档调用接口，并正确处理分页、筛选、鉴权和错误。
- **必要内容**：资源命名与请求方法；状态码的使用；请求/响应字段约定；分页、筛选、排序；登录态或令牌的基本流程；认证与授权的区别；接口文档；接口级测试。[SRC-BE-05]
- **可选或后置**：GraphQL、接口版本管理、限流、开放平台规范。
- **最小实践产出**：一份与实现一致的接口文档、一组覆盖成功与失败的接口测试、一个需要身份才能访问的接口。
- **完成表现（可检查）**：文档中的字段和状态码与实际响应一致；未登录与无权限返回不同结果；分页边界（第一页、最后一页、超出范围）有明确行为；测试能在改坏一个校验时失败；另一位同学能只按文档完成一次调用。
- **卡住时缩小任务**：只保留两个接口；用固定令牌代替完整登录流程；先不做分页，只做列表。

### 阶段 4：稳定性与部署（按项目需要）

- **进入条件**：已有阶段 3 或真实项目，准备让别人长期使用。
- **学习目标**：让服务能部署、能观察、出故障时能定位和恢复。
- **必要内容**：配置与环境变量、密钥不进入代码库；结构化日志与健康检查；超时与重试；并发的基本概念；缓存与失效；容器化或最小部署步骤；备份与回滚。
- **可选或后置**：消息队列、服务拆分、完整监控链路、压测、故障演练平台。
- **最小实践产出**：部署一个服务，附健康检查、启动说明和一份故障处理记录（例如数据库连不上或配置写错时怎么发现、怎么恢复）。
- **完成表现（可检查）**：按文档能从零启动；日志能定位一次失败请求；仓库中没有明文密钥；依赖超时不会让服务一直挂起；能按记录完成一次回滚或恢复。
- **卡住时缩小任务**：只在本机用容器跑起来；只做健康检查和日志；只演练一种故障。

## 4. 与前端及相邻方向的边界

- **与前端**：后端不对界面长什么样负责，但要对接口契约、数据正确性和权限负责。
- **与运维**：后端关注应用逻辑与资源使用；运维关注运行环境、发布与故障恢复，小团队里常由同一人承担。
- **与数据**：后端面向在线业务库（事务、低延迟）；数据方向面向分析与离线管道。

## 5. 限制与待验证

- 阶段划分与主题取舍是项目建议；没有验证过它对不同基础学生的实际效果。
- 本包不写学时、周数、薪资或就业结论，也不判断“某类人适合后端”。
- 语言与框架只给示例，不构成“必须学 Java/Go/Node.js”的结论；换语言时，请求处理、数据、错误处理这些共性仍然适用。
- 岗位样本只能说明个别招聘页面写了什么，不能当作行业统一门槛；即使某条要求可由某个阶段练习初步对应，也不代表完成阶段即达到录用标准。
