# 前端学习路线（项目编排建议）

资料ID：`LP-P01-FE` ｜ 版本 v0.1 ｜ 整理日期：2026-11-03
性质：这是项目编排的学习建议，不是岗位要求、官方路线或就业承诺。阶段先后可按学生已有基础调整，不需要按固定周数完成。

## 1. 这个方向主要做什么

前端的主要交付物是“用户能操作的界面”。日常工作包括：把需求与设计稿做成页面，处理点击、输入、加载等交互，把接口数据渲染到界面，处理样式与浏览器兼容问题，并在浏览器里定位报错和性能问题。[RM-P01-MAP]

判断一段经历是不是前端工作，可以看三个信号：产出是否主要是界面与交互；出问题是否先看浏览器渲染、控制台和网络请求；主要协作者是否包括设计、产品和后端。前端不等于“只画页面”，也不等于必须会某个框架。“前端和后端有什么不同”见 `LP-P01-COMPARE`。

## 2. 阶段路线

以下阶段是项目编排，不是 roadmap.sh 官方顺序，也不是行业统一标准。每个阶段都写清了进入条件，可以单独阅读。

### 阶段 1：从零做出第一张可交互页面

- **进入条件**：无编程基础也可以开始；有可用的电脑，能安装浏览器和代码编辑器，能管理文件。[SRC-FE-01]
- **学习目标**：不依赖框架，独立完成一个静态页面，并加上少量交互。
- **必要内容**：HTML 语义结构与常用标签、链接、图片、表单；CSS 选择器、盒模型、层叠与继承、Flex 或 Grid、基础响应式；JavaScript 变量、函数、条件、循环、数组与对象、事件、DOM 读写；浏览器开发者工具；Git 的保存与回退。[SRC-FE-02][SRC-FE-03][SRC-FE-04]
- **可选或后置**：CSS 预处理器、Tailwind 等样式方案、动画库、TypeScript、React/Vue。
- **最小实践产出**：一个单页作品（例如“个人介绍页 + 待办列表”），包含表单、列表和至少两个交互；能在本地打开，或发布到静态托管；附一段简短说明，写清做了什么、怎么运行。
- **完成表现（可检查）**：窄屏不出现横向滚动；表单非法输入有提示；交互不会整页刷新；控制台无报错；能用开发者工具定位一次样式问题；能解释自己用到的三个标签为什么这样选。
- **卡住时缩小任务**：先只做“标题 + 一段文字 + 一个按钮”；交互减到一个；照着现成设计稿仿写；暂时不做响应式，先保证桌面端可用。

### 阶段 2：调用接口并处理数据状态

- **进入条件**：完成阶段 1，或已经能写基础 HTML/CSS/JavaScript。
- **学习目标**：从一个真实接口取数据并渲染，能处理加载、失败和空结果。
- **必要内容**：JSON 结构；HTTP 请求方法、状态码、请求头与响应头的基本含义；`fetch` 与 Promise/async-await；错误捕获；把响应字段映射到界面；避免重复请求的简单做法。[SRC-FE-04][SRC-FE-05]
- **可选或后置**：框架、构建工具、状态管理库、TypeScript、跨域细节、缓存策略。
- **最小实践产出**：一个查询或列表页，接一个公开 API（如天气、汇率或公开数据集），包含搜索或筛选、加载态、错误提示与重试、空结果提示。
- **完成表现（可检查）**：断网或把接口地址改错时，页面给出能理解的错误而不是白屏；连续点击不会叠加出重复请求；结果为空时有提示；能说明“请求发出 → 响应返回 → 页面更新”的路径；能区分哪些字段来自接口、哪些是本地计算。
- **卡住时缩小任务**：先用本地 JSON 文件跑通渲染，再替换成接口；去掉搜索，只做列表；先用浏览器或 curl 确认接口确实返回数据。

### 阶段 3：用框架组织一个小应用（可选分支）

- **进入条件**：完成阶段 2；能从官方文档自学；在 React 与 Vue 中只选一个。
- **学习目标**：用所选框架完成一个多视图小应用，理解组件、状态与路由。
- **必要内容**：组件拆分与 props/state、事件处理、条件与列表渲染、路由、表单、与接口结合；包管理与构建命令的基本使用。[SRC-FE-06][SRC-FE-07]
- **可选或后置**：另一个框架、服务端渲染或静态生成、全局状态管理、组件库、TypeScript 深入。**不需要 React 和 Vue 同时学**；另一个框架可以在项目需要时再补。
- **最小实践产出**：包含列表、详情、表单三个视图的小应用，复用至少两个组件，接阶段 2 的接口。
- **完成表现（可检查）**：路由可直接访问并能刷新；组件 props 含义清楚，没有靠全局变量传值；表单校验与接口错误分开处理；能解释某个状态为什么放在该组件；构建后能本地预览。
- **卡住时缩小任务**：只做两个视图；先用 mock 数据不接接口；把路由换成简单的条件渲染。

### 阶段 4：工程化与质量（按项目需要）

- **进入条件**：已有阶段 3 或课程项目，准备与他人协作或长期维护。
- **学习目标**：让项目可安装、可检查、可交付。
- **必要内容**：代码规范与格式化、Git 分支与提交、组件或单元测试基础、构建与部署、可访问性基础（语义、键盘操作、对比度）、基础性能（图片大小、懒加载）。
- **可选或后置**：CI/CD、端到端测试、监控与错误上报、服务端渲染、微前端、设计系统。
- **最小实践产出**：给阶段 3 项目补上 lint、至少一个测试、构建与部署预览，并写一份“改了什么、怎么验证”的记录。
- **完成表现（可检查）**：换一台机器按说明能启动；测试能在改坏组件行为时失败；能说出一次可访问性或性能改进前后的差异；提交历史能看出每一步做了什么。
- **卡住时缩小任务**：只加 lint；只写一个测试；只做部署，不碰其他项。

## 4. 与后端及相邻方向的边界

- **与后端**：前端负责展示、交互与客户端状态；后端负责业务规则、数据持久化与权限校验。前端校验不能替代服务端校验。
- **与设计**：设计决定视觉与流程，前端负责实现可行性、交互细节与还原度。
- **与测试**：前端可以写组件测试；端到端与跨浏览器回归通常由测试或协作流程承担。

## 5. 限制与待验证

- 阶段划分与主题取舍是项目建议；没有验证过它对不同基础学生的实际效果。
- 本包不写学时、周数、薪资或就业结论，也不判断“某类人适合前端”。
- 官方文档会更新；引用时保留核验日期，具体版本与命令以原页面为准。
- 岗位样本只能说明个别招聘页面写了什么，不能当作行业统一门槛；即使某条要求可由某个阶段练习初步对应，也不代表完成阶段即达到录用标准。
