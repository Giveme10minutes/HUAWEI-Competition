## 2. 负向检查（不应出现或不应被命中）

- 搜索“几周”“学时”“速成”：正文不应给出固定周数或“X 天掌握”的承诺。
- 搜索“保证就业”“包就业”“学完即可”：不应出现。
- 搜索“必须同时学 React 和 Vue”“必须学 Java”：不应出现；应出现“只选一个”“语言可替换”。
- 搜索“行业标准”“官方路线”：阶段只能标为“项目编排”，不能包装成 roadmap.sh 官方顺序。
- 搜索本机绝对路径（如 `/Users/`）：`content/` 三份正文不应包含；历史 v0.2 文件中的路径问题不在本轮正文复制。
- 搜索“薪资”“11-12K”：`content/` 正文不应把单条岗位薪资写成方向结论；薪资事实只在岗位卡与 `review/job_alignment.md` 中带限制保留。

## 3. 跨文件一致性

- `LP-P01-FE`、`LP-P01-BE` 引用的来源编号（SRC-FE-01…07、SRC-BE-01…05、RM-P01-MAP）都能在 `review/sources.md` 找到。
- `LP-P01-COMPARE` 引用的 `RM-P01-MAP`、`CS-P01-BOSS-005`、`CS-P01-BOSS-010` 都能在 `review/sources.md` 与岗位卡中找到。
- 三份正文都写了“项目编排建议，不是岗位要求或就业承诺”，且都在限制节重复边界，避免只截取一段时丢失条件。

## 4. 执行记录

- 本轮仅做人工可复核设计，未调用检索接口，未记录命中率或召回率。
- 后续若执行，应保留问题、返回的资料ID、片段位置与日期；未实际执行前不得写成“检索通过”。
