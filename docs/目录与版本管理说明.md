# 目录与版本管理说明

## 目录职责

| 路径 | 内容 | 本项目版本管理 |
| --- | --- | --- |
| 根目录 | README、项目指引、交接摘要、环境样例 | 跟踪 |
| docs/ | 需求、计划、操作说明、调研结论 | 跟踪 |
| prompts/ | 智能体行为配置 | 跟踪 |
| contracts/ | 应用数据格式与样例 | 跟踪 |
| data/templates/ | 资料录入模板 | 跟踪 |
| evals/ | 人工验收案例与模板 | 跟踪，runs/除外 |
| scripts/ | 本地检查工具 | 跟踪 |
| assets/branding/ | 图标及生成说明 | 跟踪 |
| assets/diagrams/ | 项目图示 | 跟踪，图示内容仍需与当前方案核对 |
| references/raw/ | 用户提供的原始参考文字 | 跟踪，原稿不自动视作事实 |
| submissions/private/ | 含个人信息的提交包、压缩包及快照 | 本地保留，忽略 |
| tools/ | 现有第三方下载工具及其独立仓库 | 本地保留，整个目录忽略 |
| local_data/、data/private/ | 数据库、私有记录 | 忽略 |

本轮将原 `一些可用资料/` 移到 `references/raw/`，将根目录提交材料移到 `submissions/private/`；同步修改活动文档中的参考路径。提交包内原稿与独立工具仓库不改写。需求文件名暂保留历史名称，正文版本以实际内容为准。

## 本地版本管理

本项目使用独立本地 Git 仓库，主分支为 main。首次提交保存当前准备材料，后续每完成一个可验收任务再提交。尚未创建或连接远程仓库。

提交前检查变更范围、资料来源、文档链接及必要的行为验证。不要使用 `git add -f` 将已忽略的密钥、运行数据或私有提交包加入仓库。

日常命令：`git status` 查看变化，`git diff` 检查内容，`git add <具体路径>` 暂存本次任务，`git commit -m "说明本次变更"` 保存版本。

后续决定上传远程前，还需核对原始资料的可分享范围和个人信息；本次只建立本地版本记录。
