# 开工基线与检查表

日期：2026-10-31｜版本：v0.1

本文根据“把开工前准备和约定整理好”的授权设立默认执行基线。它是实施安排，不改变面向全体大学生的产品定位；用户后续指示优先。调整基线时记录原因和受影响的任务。

## 1. 现在统一的决定

| 项目 | 执行基线 |
| --- | --- |
| 产品名称 | 暂用“大学生职业探索与学习行动 Agent”，品牌名称后定，不阻塞开发 |
| 用户范围 | 全体大学生，允许未知目标、跨专业探索和不同年级；不收窄为开发实习 |
| 核心成果 | 从个人情况出发，给有依据的行动建议，记录反馈并调整 |
| 首次原型 | 平台内真实多轮追问与一个可执行任务；它不是完整 P0 产品 |
| 第一个完整流程 | 档案确认→资料检索→计划草稿→用户确认→保存→成果反馈→调整草稿→确认新版 |
| 平台职责 | AgentArts 承担实际智能体分析、知识检索与流程编排；先验证低码入口 |
| 应用职责 | 自有网页呈现档案与任务；后端保存业务状态、连接平台和数据库 |
| 技术默认 | 到业务开发阶段，默认 Python/FastAPI、SQLite、原生 HTML/CSS/JavaScript；如真实能力或团队条件不适配再记录变更；当前不安装或锁定未经验证的版本 |
| 平台接入 | 实测后实现单独适配模块；本项目内部约定不冒称华为 API 格式 |
| 模型选择 | 先用账号可用且成本可承受的模型验证；记录具体模型与配置，暂不虚构型号 |
| 初始输出 | 追问每轮最多 3 个关键问题；先做一个清晰任务，完整计划默认两周且可调整 |
| 时间预算 | 用户提供的是可投入的净时间；建议任务总估时≤周期可用时间的80%，不重复扣除已扣除的课程时间 |
| 事实与探索 | 无资料仍可协助整理经历和安排取证任务；职业门槛、薪资、日期等事实不能凭空生成 |
| 写入方式 | 模型提出草稿，用户确认后才改正式档案/计划；后端校验并写入 |
| 后续增强 | 自动采集、完整发展路径比较、机会推荐、外部提醒等仍按 P1 推进 |

## 2. 准备完成与未完成的区别

已准备：文档入口、执行基线、平台配置草稿、首轮步骤、应用层格式、样例、资料模板、访谈模板、人工测试案例、运行记录及任务看板。

必须实际操作后才能认定完成：账号可用、模型成功响应、资料检索命中、应用发布调用、业务工具连接、产品验收、访谈与试用。准备文件存在不等于上述验证成功。

## 4. 协作与完成标准

- 一次认领一个可检查任务；不同人/对话不要同时改同一份配置或接口文件。
- 修改数据格式或智能体行为时，同步相关样例和验收案例；在看板记录变化。
- 任务“完成”需有验证材料；失败或未执行分别记录，不以“文件已生成”代替运行结果。
- 只对关键业务行为、格式与错误处理做必要检查，不为简单文字调整追加无意义测试。
- 不提交密钥、真实用户档案、访谈录音或含个人信息的截图；使用本地运行记录目录。
- 已有原稿和工具保持独立；清洗资料另存，保留出处和核验状态。

## 5. 开始与发布的门槛

开始平台任务：取得创建/调试权限，保存第一版配置，选一个验收案例即可，不需等所有职业资料齐备。

进入业务开发：至少一个案例在平台跑通，并验证真实发布调用和工具连接方式；确定请求、返回、失败状态与网络条件。

开始真实用户试用：完成适用 P0 功能检查、用户数据隔离与删除验证，资料来源可追溯，明确实际覆盖范围。

最终提交：以本届规则核对材料，核验成果与指标；尚未验证的结果如实说明。

赛事依据见 [赛事规则核验](赛事规则核验_2026-10-31.md)。平台权限的用户确认不等于应用运行已经验收。
