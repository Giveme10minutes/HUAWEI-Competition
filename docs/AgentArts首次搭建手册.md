# AgentArts 首次搭建手册

目标：取得一次真实的多轮探索结果。本文不假定当前控制台按钮和字段名称，具体入口以账号页面为准。

## 操作顺序

1. 打开 AgentArts，确认创建和调试权限，记录账号内显示的区域、模型与费用限制；缺失权限时记录问题。
2. 选择可用的单智能体或适合多轮对话的低码创建方式，应用暂名“大学生职业探索助手”。
3. 将 [行为配置](../prompts/career_agent_v0.1.md) 中分隔线内的内容放入角色/提示词等对应位置；不把整份开发文档当提示词。
4. 暂不连接不存在的工具、岗位库或业务数据库。选账号内实际可用模型，记录名称与设置。
5. 用案例 E01 开始，按案例里的后续输入继续。保存完整回答与人工判定。
6. 同样检查 E02、E03，再看其余失败边界案例。配置变化另存版本，记录原因。
7. 基础行为通过后接入少量已核实资料；对“能引用”和“找不到资料”分别验收，再考虑发布 API 与业务工具。

## 首次通过标准

- 问题跟随用户回答，而非机械一次性发问卷。
- 不因“喜欢短视频”直接认定职业，不强推开发方向。
- 行动清晰、有时间和成果要求，能在用户条件下开始。
- 无职业证据时不编造事实；无保存工具时不说已保存。

## 保存证据

在本地 `evals/runs/` 下按日期和应用版本保存匿名运行记录；填写 [模板](../evals/运行记录模板.md)。只展示必要内容，避开账号、密钥及个人信息。

平台行为与示例不同不一定是失败，按案例预期行为判断，不逐字对照答案。此阶段不要求强制结构化 JSON；应用接入后再将模型结果转换为 [应用内部约定](应用数据与接口约定.md)。
