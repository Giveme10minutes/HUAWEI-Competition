# 多查询与 HyDE 对照工作流手测版

用户要求本地生成测试版本，由用户手动导入和运行。交付文件位于 `local_data/retrieval_comparison_v0.1/workflow_multiquery_hyde_test.jsonl`。源文件是本地 `local_data/multiquery_pilot_v0.1/workflow_threshold0_latest.jsonl`，它对应历史上已导入的阈值 0 诊断配置。当前云端草稿需在导入前另外核对。

## 执行路径

- 原意图识别进入资料检索路径时，保留原“检索关键词提取 → 知识检索”。
- 在原检索之后串联三组“扩展查询 → 独立知识检索”，角度依次为问题改写、技术术语、相关子主题。各生成器使用同一个学生输入，每路只生成一条查询。
- 接着运行“HyDE 假设文档 → 独立知识检索”。假设文档只进入此路检索节点。经典 HyDE 使用假设文档的向量做稠密检索，本版把文本交给平台的混合检索做对照。[HyDE 原论文](https://aclanthology.org/2023.acl-long.99/)
- 分析和复核同时收到五路的真实 `output_list`，保留原 `sources` 引用，新增四组数组输入。按片段相关性与出处使用证据，并合并重复内容。生成的假设文档和查询不作为引用来源。

实际文件有 20 个节点、22 条边。与源文件比较，移除旧游离多查询试验节点，新增四组生成器和检索节点，原“知识检索 → 职业资料与方向分析”一条直连替换为试验链。原检索节点、意图分支、规划与结束接口及关联资源保持原值。五路继承同一绑定、过滤和检索配置，模式为混合、阈值为 0、topK 为 3。阈值 0 用于诊断。当前链路串行，进入资料检索路径时比原流程多四次生成和四次检索。

## 手动导入与测试

1. 在 AgentArts 导出当前草稿留作恢复基线，确认工作流身份及有没有其他窗口的新改动。交付文件沿用“职业探索_协作流程_v01”的资源 ID，导入预览勾选已有工作流会更新草稿。发现新改动时，用最新导出生成新副本后再核对差异。[操作手册](AgentArts工作流JSONL操作手册.md)
2. 通过“导入 AgentArts 工作流”选择该 JSONL，检查预览中的工作流与关联资源。导入后重开草稿，看四组新节点及其引用是否存在。
3. 用一条明确会触发资料检索的输入试运行。例如“我是计算机相关专业学生，想比较前端和后端开发的工作职责和任职要求。我还没有确定方向，请帮我比较。”如果没进入资料分支，先查实际意图输出。
4. 在节点详情逐路记录实际查询文本、策略、阈值、topK、召回文档、片段正文和分数。检查三条扩展查询是否有区别，以及 HyDE 检索输入是否为生成的假设正文。各路召回分数分别看，比较新增的相关片段、重复片段与空结果。
5. 读最终回答，检查可追溯引用来自实际召回，重复片段没有当作独立证据，假设正文没有被当成来源。若相关证据不足，应说明缺口。仅检查查询生成或仅看节点成功状态时，按单节点结果记录。

## 重新生成与验证范围

从项目根目录运行。若云端有更新，把 `--source` 换为最新导出，并使用一个尚未存在的 `--output` 文件名。生成器基于实际 LLM、知识检索和连线结构，要求源文件仍包含旧的游离“多查询扩展试验”节点，结构不符时停止。

```sh
python3 scripts/prepare_retrieval_comparison_workflow.py \
  --source local_data/multiquery_pilot_v0.1/workflow_threshold0_latest.jsonl \
  --output local_data/retrieval_comparison_v0.1/workflow_multiquery_hyde_test.jsonl
```
