# 职业探索与学习行动 Agent 开发计划

版本：v0.3｜日期：2026-11-03｜文件名沿用旧版

用户确认按本轮讨论修订下一版路线：少量多 Agent＋知识库＋现有业务后端，减少 MCP 与运行时 Skill 依赖。具体角色粒度和一轮修订上限为实施默认，平台细节与收益待验证。本次仅完成文档更新，不代表已经迁移或部署。原计划完整保留于[历史版](开发计划_v0.1_历史_2026-10-31.md)。需求依据为[需求 v0.5](职业探索与学习行动Agent_需求文档_v0.1.md)。

## 1. 当前基础与目标

已具备本地 React/TypeScript/shadcn 界面、FastAPI/SQLite、已发布低码单 Agent 调用、流式显示、对话管理、人工线索和规划确认/历史，以及已确认记录随消息传入。实际验证范围见progress.md，不重新创建这些功能。当前仍为单用户本地原型，多 Agent、自动草稿整理、完整成果闭环及多用户能力尚未实现。

目标闭环：模糊表达→经历探索与确认→有来源的方向比较→差距和阶段目标→学习实践草稿→确认保存→成果反馈→按原约定评估→调整草稿→确认新版。服务计算机相关专业大学生，不扩成校园全能助手，不将任务管理替代职业规划。

## 2. 架构与分工

一个探索协调入口，按需调用职业资料与方向分析、阶段规划与行动、质量复核三个角色。固定依赖通过工作流连接；简单问题直接回答，信息不足只追问。首版不多层嵌套，不无限互评。知识库提供依据；角色提示词承载关键方法与约束；后端执行预算、版本及确认保存。暂不新增 MCP，保留项目 Skill 作为方法源，不要求平台运行时加载。

前端与数据库保留。新平台连接通过现有独立适配层接入，但协议与事件必须实查，不能假定兼容旧接口。迁移成功前保留单 Agent 路径，失败可恢复旧配置，不覆盖已有记录。

## 3. 开发顺序与阶段验收

下表为阶段验收框架；M1—M3已有局部配置与运行，最新结果见progress.md及多Agent核验记录，不能将整阶段判通过。人员与投入未确认，不承诺日期。

| 阶段 | 工作与交付物 | 验收条件 |
| --- | --- | --- |
| M1 现状与能力核验 | 核对现有部署版本、账号多智能体入口、工作流输入输出、等待输入、知识检索与发布协议；形成能力核验记录 | 明确可复用资源、实际限制及最小编排方案，不因旧文档重复建资源 |
| M2 角色与资料准备 | 拆分四角色提示词；定义最小交接格式、来源/推断/未知标记、错误结果；复核少量跨领域资料 | 每个角色职责与输出明确；资料可追溯；关键规则不依赖偶然检索；不把待审采集资料批量转正式库 |
| M3 云端最小协作 | 按需路由，先跑通资料分析→规划→复核的顺序，并能在资料不足时返回追问 | 能看到真实角色结果传递，引用未丢失，复核问题有处理；保留草稿与发布版本区别 |
| M4 接入现有业务闭环 | 适配新调用与流式/失败状态；从对话整理待确认线索和结构化规划草稿；接程序预算校验；补成果与调整记录 | 用户确认前不改变生效记录，确认后刷新可读；评审使用原约定和版本；失败保留原记录、不重复写入 |
| M5 小范围对照 | 运行MA01模糊表达、MA02方向比较、MA03反馈调整，与原单Agent使用相同资料和输入比较 | 记录具体通过/不足、调用次数和耗时；按收益及代价决定保留拆分或合并角色，不凭架构名称判优 |
| M6 试用与交付 | 对照全部P0缺口，完成必要用户隔离和资料删除等要求后开展真实试用，整理演示与配置 | 实际效果、覆盖领域及未完成项如实记录；原15例不因局部测试批量通过；赛事要求另行核实 |

M1通过后再确定云端资源配置；M2可先整理方法与已有资料。M3通过后接入M4，保留旧调用路径；M4完成后开展端到端M5。任何尚未实现的P0不因架构迁移而降级。正式发布与首次部署按既有用户接手部署约定执行，文档修订不等于部署授权。

## 4. 最小交接与数据要求

角色输入包含本轮问题、必要对话、当前已确认资料及规划版本；待确认线索单独标记。资料结果带来源ID、链接、日期、原文片段、适用范围和未知项。规划结果需包含方向依据、差距、阶段目标、关联行动、分钟预算、成果和验收要求、调整原因。复核输出具体问题及其依据，不冒充事实认证。

先复用现有数据结构，必要增量修改前检查实际代码并备份数据。预算按周期净可用分钟计算，当前80%为实施基线，不能重复扣除；用程序求和和比较。模型不可自行确认、保存或声称后台提醒。当前会话记忆不等于业务记录，也不保证旧云端记忆已清除。

## 5. 资料与验证策略

资料按职业路径、亲历案例、学习实践、规划方法分类，先复用再按检索质量决定分库。优先用户要求的交流平台实际经历，岗位和资格分别核对原始依据；保留原始文件及pending状态。人工审核导入优先，自动采集和通知后置。

只执行正常流程与修改相关必要回归，覆盖计算机类不同基础和目标状态。不反复重跑已通过边界测试。记录环境、模型/配置版本、资料版本、最终回答、有限耗时和错误，不记录思考或凭据。复核Agent和多Agent数量都不是质量证明；耗时增加、依据丢失或重复追问时优先缩短流程或合并角色。

## 6. 下一项工作与完成记录

下一项为M1：只读核对账号与现有发布状态，明确如何实现按需路由和顺序协作；同时以现有方法包准备M2角色拆分，尚不替换现有应用或重跑旧测试。文件准备不算云端验证。

每个可验证里程碑同步progress.md和必要证据；决策变化同步decisions.md，标明用户确认、实施默认或待验证。提交前检查差异与忽略范围，只提交本任务文件。保留原应用、数据库、第三方tools、私有提交及用户新增文件。
