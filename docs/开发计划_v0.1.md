# 职业探索与学习行动 Agent 开发计划

版本：v0.1｜建立日期：2026-10-31｜状态：建议计划，尚未确认人员投入和具体日程

依据：[需求文档 v0.3](职业探索与学习行动Agent_需求文档_v0.1.md)。目标用户保持为不同专业、年级的全体大学生。本文把需求拆成阶段与验收任务；每阶段的成果通过检查后再推进，不把设想当成已完成功能。

## 1. 首次可用版本的交付目标

用户能够提供个人情况与当前困惑，经智能体追问、查询资料后，确认一项职业探索或学习实践任务；提交成果或困难后获得反馈，修改近期计划，并在下次打开时继续。

最低完整演示链条：

个人情况与阶段约束 → 有来源的探索建议 → 用户确认行动计划 → 保存任务 → 提交成果 → 反馈与调整草稿 → 用户确认 → 保存新版本。

先用 AgentArts 调试界面验证分析与编排，随后通过接口连接业务数据和自己的网页。暂不要求多 Agent 架构，具体开发入口、节点和部署方式在账号实测后决定。

首次原型只是过程检查点，不能称作已经完成全部 P0 需求。首版发布前需核对需求文档中的全部 P0 项和适用验收场景。

## 2. 当前起点与依赖

- 已有需求文档、来源台账、个人经验资料评审和作品信息表初稿。
- AgentArts 创建、模型调用、知识检索、发布及业务工具尚未实测。
- 尚无本计划已验收的产品实现、真实用户访谈、跨专业岗位库和试用结果。
- 队伍成员在赛事表中已有填写，具体开发职责、每周可投入时间、校内提交日期仍需确认。
- 本届官网公开赛题、评分和阶段材料已于2026-10-31核实，见《赛事规则核验》；上传截止、重传规则、本校日期和云资源范围待确认。用户已确认可在 AgentArts 创建调试，实际应用仍未验收。

不预设固定完成日期。取得实际截止时间及人员时间预算后，再按下列任务估算、预留联调和交付时间并倒排；不得把公开报名截止时间直接当作作品截止时间。

## 3. 阶段任务与验收

表中的状态是本计划初始状态，不代表用户在其他对话或平台上没有做过相关工作；开始任务前应核对当前事实。

### 阶段 A 跑通平台原型

目标：确认平台可用，并让智能体完成一次合理的追问与行动建议。

| 编号 | 任务 | 交付与验收 | 状态 |
| --- | --- | --- | --- |
| A1 | 核对平台和参赛条件 | 记录账号可用状态、创建入口、模型权限、资源限制、已知截止日期与规则链接；未知项明确列出 | 待核对 |
| A2 | 创建智能体与基础行为配置 | 在平台调试界面完成一次真实多轮对话，配置内容保存为项目文件 | 未验收 |
| A3 | 设计三个基础案例 | 覆盖未定向、比较方向和已有目标；至少一例非计算机背景，并含阶段或时间约束 | 未验收 |
| A4 | 调整追问与任务输出 | 案例中能依据回答继续追问，允许未知；每项行动有具体动作、时间和结果记录要求 | 未验收 |

此阶段尚无职业资料时，只测试追问与探索任务，不把模型给出的岗位或薪资内容标为已核实。

通过条件：三个案例均能完成“了解情况—确认当前问题—提出可执行行动”；不直接由兴趣标签断定职业，不强推技术岗位，不忽略时间约束。

### 阶段 B 接入资料并验证实际需求

依赖：A2 可用。资料准备和访谈可以并行进行。

| 编号 | 任务 | 交付与验收 | 状态 |
| --- | --- | --- | --- |
| B1 | 建立少量可核验资料包 | 先选跨领域示例，记录职业介绍、岗位和学习/实践资源的来源、日期、适用范围；开发样例不等于正式覆盖已达标 | 未验收 |
| B2 | 接入知识检索 | 问题能检索到正确资料，建议能定位引用；查不到时明确不足 | 未验收 |
| B3 | 小规模访谈 | 先访谈两名情况不同的同学检查问题，再扩展至需求文档建议的跨专业样本；保留匿名经历、障碍和反馈 | 未开展 |
| B4 | 修正核心任务流程 | 将实际问题映射到已有需求，记录保留、修改和延期的理由；不因单人意见推翻整体定位 | 未验收 |
| B5 | 验证行动计划 | 任务关联阶段目标，预算可行，既有必要学习也有适当的行动实验；案例运行结果留档 | 未验收 |

通过条件：建议引用可定位；资料不足时不编造；至少一个经过访谈修正的案例在平台上走通。正式支持领域的资料数量与覆盖要求仍按需求文档第 8 节检查，不用少量演示资料冒充完整知识库。

### 阶段 C 接入持久化数据与业务工具

依赖：平台流程基本稳定；先验证发布调用及工具连接能力，再扩展业务功能。

| 编号 | 任务 | 交付与验收 | 状态 |
| --- | --- | --- | --- |
| C1 | 验证已发布智能体调用 | 自有后端成功调用平台并处理失败，密钥不进入网页 | 未验收 |
| C2 | 保存个人档案和关键事项 | 用户确认后保存；修改信息后可读回，重启后仍存在；用户数据隔离 | 未验收 |
| C3 | 保存计划和任务 | 用户确认后创建；包含目标、动作、预算、验收项和状态；重试不重复创建 | 未验收 |
| C4 | 提交成果并反馈 | 支持通用文本与作品材料，分别记录自述、提交证据和评估结果；无内容可读时说明限制 | 未验收 |
| C5 | 调整与版本记录 | 修改预算或反馈困难后生成草稿；拒绝不改变当前计划，确认后保存新版且保留历史 | 未验收 |

通过条件：通过平台和业务工具完成最小完整链条，重新打开或重启后能继续；调用失败不丢数据、不重复写入。

后端与数据库的具体选择尚待确认；此前建议的 FastAPI 与 SQLite 可作为小规模原型选项。只在需要时写业务代码，避免同时另写一套重复的智能体流程。

### 阶段 D 完成网页并准备试用版本

依赖：C 阶段接口可联调。页面草图可提前设计。

| 编号 | 任务 | 交付与验收 | 状态 |
| --- | --- | --- | --- |
| D1 | 最小网页流程 | 档案、探索对话、任务计划、成果反馈可访问；能看清已保存与待确认状态 | 未验收 |
| D2 | 数据与内容管理 | 支持资料审核/更新、来源状态、用户更正/导出/删除、必要的运行错误记录 | 未验收 |
| D3 | 对照 P0 需求验收 | 检查 FR-01—FR-12 中的 P0 部分和对应 AC 用例，记录通过、失败和未验证项 | 未验收 |
| D4 | 跨专业真实试用 | 按需求文档招募不同专业用户，记录行动启动、成果、困难、调整及退出原因；使用周期据实报告 | 未开展 |
| D5 | 效果评估与问题修复 | 按需求文档准备案例与对照评估，报告具体分子/分母、失败案例、耗时与成本 | 未开展 |
| D6 | 参赛材料 | 根据本届实际规则补齐方案、操作说明、真实 Demo、代码/配置、复现步骤和演示材料 | 未验收 |

通过条件：适用 P0 验收项通过，展示结果与真实实现一致，第三人可按文档复现。不将压缩演示称为真实两周试用；未达到的效果明确报告。

## 4. 首版优先级与延期项

先完成：个体情况与阶段约束、可靠资料检索、探索与学习任务、成果反馈、计划调整、记录保存及最小界面。

后续增强：许可来源的定时采集、完整升学/就业路径比较、校内外机会推荐、外部提醒、作品平台接入及更长周期规划。它们继续保留在需求中，不应挤占最小流程的验证。

若实际时间不足，先向用户呈现尚缺哪些 P0 功能及其影响，再调整交付范围；不能暗中将 P0 降级，也不能以换成计算机专业用户来缩减工作。

## 5. 角色分工建议

实际人选与投入未确认，先按角色拆分：

| 角色 | 主要任务 | 协作要求 |
| --- | --- | --- |
| 产品与资料 | 访谈、来源审核、职业资料、任务标准 | 与平台负责人一起核验推荐依据和案例 |
| AgentArts 开发 | 行为配置、检索、编排、工具连接、案例评估 | 保存配置版本，明确输入输出和失败状态 |
| 应用开发 | 业务后端、数据库、网页、联调与运行记录 | 与平台负责人先跑通一个接口，再扩展 |

三人均需理解完整使用流程。阶段 A 先共同跑通一例，再分工，避免分别完成后才第一次连接。

## 6. 任务完成与记录方式

状态统一为：未开始、进行中、待验收、完成、受阻。每项任务记录负责人、必要依赖、实际用时、验证材料和剩余问题；目前未提供的负责人留空。

每次完成任务至少留下一个可检查的结果：配置文件、匿名访谈记录、来源条目、运行结果、测试记录或演示截图。验收失败则记录原因并修复；涉及产品方向变化时同步需求和项目摘要。

本计划不会自动随其他对话的进展更新，完成任务后应由当次负责者记录实际状态。

## 7. 现在的第一个任务

执行 A1—A2：进入 AgentArts，确认可以创建和调试应用，建立一个职业探索助手并完成首次真实对话。

测试输入：“我是大一学生，不知道以后想做什么，参加过社团活动，每周可以用三小时探索。”

验收：能追问具体经历，允许未知，不直接按兴趣标签决定职业，并最终提出可在预算内完成、能记录体验的下一步行动。

完成这一例后再做 A3—A4。若平台权限尚不可用，继续准备匿名案例、初版行为配置和访谈，不伪造平台成功结果。
