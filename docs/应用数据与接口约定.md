# 应用数据与接口约定

版本：0.1。用于后续网页、后端与 AgentArts 适配时统一业务含义。它不是华为官方 API，也不是已经实现的服务。平台请求地址、鉴权、会话、流式响应和工具协议必须实测后另记。

## 1. 数据规则

- ID 使用服务端生成的不透明字符串；用户身份从已验证会话取得，不相信模型或浏览器自报的 user_id。
- 时间戳用带时区的 ISO 8601，日期显示采用 Asia/Shanghai；关键事项有适用范围、来源和核验状态。
- 未知使用 null，不能用0或空列表假装已知；空列表表示已知为空。
- 对话中“用户说过”、资料中“有出处”、数据库中“已保存”分别记录。
- 模型输出先校验，再形成草稿；工具侧再次检查所有权、预算与版本。确认记录由应用端生成，不接受模型自报“已确认”。

## 2. 状态

计划：`draft → active → superseded`。拒绝草稿标为 `rejected`；旧计划仅在新版被确认且写入成功后变为 superseded。

任务：`not_started / in_progress / needs_evidence / needs_revision / passed / cancelled`。模型生成一份新计划时只创建 not_started 任务。任务证据等级独立记录为 `self_reported / submitted / task_verified`。

对话阶段：`clarify / explore / plan / review`；不是用户终身状态，允许来回切换。

## 3. 计划格式

格式与有效示例见 `contracts/plan.schema.json`、`contracts/examples/plan.json`。预算以分钟为单位：用户两周净可用480分钟时，建议任务合计≤384分钟。未知预算不能激活完整计划，应先补问；仍可给标注估时的单项探索建议。

任务必须包含 purpose、actions、estimated_minutes、deliverable、acceptance、cost_note；默认两周，但 period_days 可改。引用 source_ids 必须属于该次提供且已审核的资料；无来源的探索任务用空列表，不伪造引用。

## 4. 后端业务边界

以下是待实现的逻辑操作名称，不预设平台工具协议或 HTTP 路径。

| 操作 | 输入 | 输出与约束 |
| --- | --- | --- |
| read_profile | 当前身份 | 仅该用户已保存的档案与版本 |
| propose_profile_update | 档案变更草稿、基础版本 | 不写正式记录，等待用户确认 |
| query_sources | 领域/职能、条件、关键词 | 带来源、日期、证据片段、核验状态和覆盖限制 |
| propose_plan | 信息、资料与基础计划版本 | 校验后返回草稿，时间与引用须通过检查 |
| confirm_plan | draft_id、确认动作、请求标识、基础版本 | 原子保存，重复请求返回同一结果；版本冲突不覆盖 |
| submit_evidence | task_id、可读成果、请求标识 | 校验所有权，保存提交版本；模型评估另附版本 |
| propose_adjustment | 当前计划版本、原因、反馈 | 新草稿及修改说明，原计划仍有效 |
| confirm_profile_update | 草稿及用户确认动作 | 校验所有权、版本后保存 |
| export_or_delete_records | 当前身份、用户明确请求 | 导出或删除本人的业务记录，删除后检索不可再命中 |

## 5. 错误与恢复

应用统一错误类别：validation_error、unauthorized、forbidden、not_found、version_conflict、upstream_unavailable。由适配层把平台实际错误转换，不把平台报错直接解释成用户失败。

超时、工具失败、记录缺失分别提示；数据库写入结果未知时按请求标识查询，不直接重复创建。旧提交的迟到评估不能覆盖新提交结果。日志记录 request_id、配置/资料版本、耗时和状态，避免保存完整个人信息和密钥。

## 6. 本阶段未决定
