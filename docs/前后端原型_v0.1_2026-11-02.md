# 前后端原型 v0.1（2026-11-02）

## 状态与范围

已完成一个**单用户、仅本机访问**的探索助手原型，用于验证“从一句困惑开始对话 → 保存会话 → 人工维护个人线索 → 逐步形成并确认规划”的最小闭环。本轮不重写职业规划方法，不修改云端提示词、模型、知识库、鉴权或部署，也未实现多用户隔离、公网部署和自动档案抽取。

界面中文，首次打开即可在输入框表达困惑，不要求先填写专业、兴趣、优势、目标、时间或预算。没有真实内容时显示空状态，不伪造建议、引用或完成进度。

## 实现结构

- `backend/config.py`
  - 仅后端读取根目录 `.env`；真实环境变量优先；不创建或覆盖 `.env`。
  - 低码配置键：`AGENTARTS_LOWCODE_URL`、`AGENTARTS_LOWCODE_API_KEY`；超时 `AGENTARTS_LOWCODE_TIMEOUT`（默认 180 秒，限制 10–600 秒）。
  - 浏览器的 `/api/meta` 只返回“是否已连接”，不返回 URL、密钥、模型或平台信息。
- `backend/database.py`
  - SQLite + WAL；表：`conversations`、`messages`、`profile_items`、`plans`、`plan_versions`。
  - 启动时把上次中断、仍为 `pending` 的用户消息标为 `failed`，保留内容供重试，不自动重发。
- `backend/agent.py`
  - 独立于网页和数据库的 `AgentClient` 适配层；`LowCodeAgent` 复用已实测的低码 HTTP/SSE 协议和 URL 校验、禁止重定向逻辑。
  - 只收集最终回答；忽略 `reasoning_content`、插件与工具内部载荷；失败映射为中文提示，不打印响应体、URL 或密钥。
- `backend/app.py`
  - 提供会话、个人线索、规划接口；`create_app(settings, agent)` 支持注入假 Agent 做离线测试。
  - `/api/conversations/{id}/messages` 以 `client_id` 幂等保存用户消息；`/api/messages/{id}/respond` 以 `reply_to` 唯一约束避免重复助手回复。
- `frontend/`
  - 原生 HTML/CSS/JavaScript 三栏界面：左侧会话列表，中间探索对话，右侧“个人线索 / 职业规划”。
  - 发送、回复、失败、重试状态可见；保存失败恢复输入；调用失败保留已保存消息；刷新后不会自动重发。
  - 个人线索新增后均为“待确认”，修改后回到“待确认”；来源区分“我的自述 / 助手推断（待核实）”。
  - 规划区分草稿、已确认、历史版本；确认新版本会把上一已确认版本标为历史；历史版本只读。
  - 用户和模型文本均先转义；助手回答只渲染极简安全 Markdown，不解析原始 HTML 或链接。
- 测试
  - `tests/test_webapp.py`：6 个应用层用例，使用临时数据库和 `FakeAgent`，不访问云端。
  - 原有 `tests/test_lowcode_agent.py` 11 个协议用例继续通过。

## 实际验证结果

验证环境：本机 macOS，项目 `.venv`（Python 3.15.2），低码接口使用现有本地配置。未记录或输出凭据值。

1. **离线测试**
   - `.venv/bin/python -m unittest discover -s tests -v`
   - 结果：17 项通过，0 失败（应用层 6 项 + 低码协议 11 项）。
2. **真实 Agent 对话**
   - 通过网页 API 创建会话并发送“你好，我是一名大一学生，我很迷茫，不知道自己喜欢什么，也不知道以后能做什么。”
   - 收到非空最终回答（491 字），用户与助手消息均为 `complete`。
   - 在同一会话继续发送一条补充，收到非空回答（621 字）；刷新/重启后仍能读取同一会话的 4 条消息。
   - 用无头 Chrome 打开 `http://127.0.0.1:8000`，在网页内打开该会话、输入并发送第三条消息；网页显示“助手正在回复”，约 14 秒后追加非空最终回答（884 字），无失败提示。
   - 数据库检查：6 条消息全部 `complete`，保存内容不含 `reasoning_content`，前端静态文件不含低码 URL/密钥。
3. **重启持久化**
   - 停止并重新启动本地服务后，`GET /api/conversations/{id}` 仍返回标题、4 条消息及最终回答；证明 SQLite 持久化生效。
4. **个人线索**
   - 新增为“待确认”；确认后为“已确认”且有确认时间；更正内容后自动回到“待确认”、确认时间清空；删除成功。
   - 另用无头 Chrome 在页面完成新增 → 确认 → 更正 → 删除，删除后界面回到空状态。
5. **规划版本**
   - 新建草稿 → 确认 v1；再建 v2 并确认 → v1 变为 `superseded`，v2 为当前已确认版本；尝试修改已确认版本返回 409。
   - 另用无头 Chrome 在页面保存并确认 v1、再保存并确认 v2，历史显示“第 2 版已确认 / 第 1 版历史版本”。
   - 同时存在已确认版本与草稿时，顶部状态显示“第 2 版草稿待确认”，不再被已确认状态覆盖；复核后已清理这两版验证数据。
6. **失败与未连接路径**
   - 离线测试验证：调用失败时用户消息保留并标为失败，重试不新增用户消息；未配置 Agent 时返回 503，不生成假回答。
7. **空状态**
   - 清除验证数据后重新启动：会话列表为空、个人线索为空、规划为空，首页返回 200。验证用的临时对话/线索/规划数据已清理，不作为产品内容展示。

## 已知限制

- 单用户本地原型，无登录、权限和多用户隔离；不要直接开放到公网。
- 只做最终回答展示，不做逐字流式输出；一次回复期间界面锁定发送和会话切换。
- Agent 会话上下文依赖低码平台的 `x-hw-agentarts-session-id`；本轮未验证平台侧会话历史/清理策略。
- 本轮不自动从聊天抽取档案，不要求模型输出结构化 JSON；个人线索和规划均需用户手动录入、修改和确认。
- 规划只有单一“我的职业规划”，支持版本历史；不支持多个规划、协作、提醒或任务打卡。
- 未修改或重新部署云端 AgentArts 应用；真实回复质量取决于现有云端提示词和知识库，不代表规划方法已验收。
- 未重跑原 15 例人工验收，不将本次局部验证写成完整产品验收通过。
