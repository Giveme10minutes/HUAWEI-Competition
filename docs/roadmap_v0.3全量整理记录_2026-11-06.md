## 组织方式

没有对所有文件套用同一模板，按对象类型分别处理：

- 语言类写“语言定位、运行与工具、语法与核心概念、典型用途、与相邻语言的区别、学习路径”，HTML 与 CSS 按标记语言和样式语言组织，没有硬套包管理与测试框架。
- 框架与库类写“解决的问题、核心概念、生态与配套工具、适用场景、与相近框架的区别、上手顺序”，GraphQL 按其接口查询语言与协议属性处理。
- 工具与平台类写“用途、关键概念、日常操作、与相邻工具的边界、上手顺序”，云平台不写价格、区域数量等易变信息。
- 职业方向类写“方向定位、常见工作与交付、能力与工具、与相邻角色的边界、入门顺序、判断是否适合的观察线索”，并明确是学习路线视角，不是具体岗位招聘要求。
- 基础能力与新兴角色按实际内容组织；AI 新兴角色逐份说明业界界定尚不统一，不把厂商宣传当作定论。
- 入门变体（36、58、74、80）只保留最小起步范围，技术清单按实际需要列 5—6 项，没有为凑数补条目。

每个 H2 标题都带对象名，正文与“来源”行脱离上级标题仍可独立阅读；未设置版本记录、整理经过、关键词索引一类切片。
