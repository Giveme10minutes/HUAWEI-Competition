# Agent 与探索记录联动 v0.1

日期：2026-11-08。用户要求暂停工作流行为研发，先联动本地前后端的线索与任务栏；随后完成根目录.env配置。此次不修改或发布云端草稿。

## 实际实现

- 兼容发布工作流的HTTP/SSE：message.data.text只在node_type=End时转发；workflow_finished.data.status.code=1是本次实测成功状态，outputs.responseContent提供最终回答，end终止。保留原单Agent content/summary_response协议，忽略中间模型及思考。此前单Agent适配器读不到最终回答，已依据真实工作流响应修正。
- 每条完整助手回答下新增“整理线索”“整理规划”。显式点击才追加一次工作流调用，使用独立随机会话，不污染原对话。输入最多16条相关已完成消息且限制总长度；不读取其他对话。返回是候选预览，不直接写业务记录。
- 线索按类别、来源、用户原话整理。后端验证quote逐字出现在用户消息，不能使用助手原话作为个人事实证据。候选在面板审核后放入已有编辑表单，先保存为待确认，再确认用于对话。原话支持不证明语义概括必然正确，仍需用户审核。
- 规划整理到现有编辑区，以新草稿保存，不就地覆盖已确认版。若替换未保存编辑会提示。文字四字段不变，扩展task_items和available_minutes。来源回答中动作、目标、估时、成果及验收不全的行动不自动补造任务，可手动补齐。
- 行动与规划版本共同持久化：名称、关联目标、具体动作、估时分钟、提交成果、原验收。周期净可用总分钟数用于后端确定性80%预算校验，超出拒绝保存；必须填写阶段目标。SQLite启动时增量添加两列，旧记录任务默认为空，不破坏原记录。
- 新“学习行动”栏只显示当前已确认规划的任务。开始学习/反馈成果会把版本号、目标、动作、估时、成果和原验收放入输入框；用户检查后手动发送。已确认任务也随当前记录快照传入助手，草稿不进入生效上下文。

## 操作

打开本机 http://127.0.0.1:8000 ，刷新页面。

1. 正常对话后点“整理线索”，对照原话放入表单，保存并确认。
2. 获得规划回答后点“整理规划”，在职业规划面板审核文字、周期总分钟和行动；必要时补齐，再保存草稿或确认。
3. 到“学习行动”，点击开始学习或反馈成果，检查输入框再发送。

API新增POST /api/messages/{message_id}/extract，body.kind为profile或plan；返回候选items或plan及source_message_id。不自动保存。现有规划写API在原文字字段外接受task_items与available_minutes；原contracts/plan.schema.json不是此本地API新增结构的替代定义。

## 限制

这是记录联动首版，不是完整成果验收系统。没有独立任务完成状态、成果附件、自动评审通过、自动抽取或数据库工具调用。反馈保存为普通对话消息，旧规划中的行动保留。预览编辑未保存时刷新会丢失，与现有表单一致。模型返回不合格式会报错并保留原记录，不以文字猜测静默写库；尚无格式自动重试。跨模型、长会话和新工作流全部分支行为未在本轮重测，M3与原15例不因接口联动通过而整体通过。当前仍是单用户本地原型。
