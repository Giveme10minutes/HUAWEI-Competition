## 3. 字段

主表字段对应 `data/templates/job_import.csv`，并增加：

- `salary_text`：平台原文薪资，未做统一换算；
- `job_status`：高校平台原文“招聘中”；BOSS 聚合页不显示，记“未显示”；
- `source_platform`、`source_status`：来源与可读范围；
- `raw_path`、`discovery_url`：原始快照与发现页；
- `notes`：该条的采集边界。

字段规则：

- **必需 / 优先**：原文出现“优先、加分、更佳”的条目进入 `preferred_skills`；其余进入 `required_skills`。没有“优先”表述时 `preferred_skills` 记“未明确列出”，不反推。
- **学历 / 届别 / 到岗**：只摘录原文出现的内容；未出现记“未知”或“未显示”。未提供毕业时间的学生不能被判断为符合某届招聘资格。
- **职责**：高校平台取职位描述；BOSS 聚合页摘要可能同时含职责与要求，且可能被平台截断，已在 `notes` 标注。
- **日期**：`published_at` 是平台显示日期，不是采集日期；采集日期统一为 2026-11-02。

## 4. 采集方法与平台限制

1. **高校就业平台**：通过 `jobs.ynu.edu.cn/module/getjobs` 公开列表接口与 `/detail/job?id=…` 详情页读取，详情页内嵌 `PAGE_DATA`，字段完整。按 21 个行业门类各取约 3 条，并补充实习与关键词岗位；公告类、已截止、正文过短的条目被剔除。
2. **BOSS直聘**：站内搜索跳转登录页；仅使用搜索引擎可索引的公开 SEO 聚合页（`activity.zhipin.com/zhaopin/…`），经 `r.jina.ai` 只读代理取得列表摘要。未使用账号、未提交验证码、未绕过验证。详情页提示“登录查看完整内容”，因此本样本不含 BOSS 的完整正文。
3. **鱼泡直聘**：首页、岗位页与 SEO 页均返回阿里云 WAF 滑块验证；经只读代理仍为 Access Verification。**本轮未取得可核验正文，未采集，也未尝试绕过。**
4. **58同城、智联招聘**：返回验证码或安全验证，未采集。猎聘、职友集、实习僧可作为后续候选来源，本轮未逐条解析。
5. 未使用政府宣传推文作为岗位依据；岗位职责与硬条件只对照招聘原文。

## 5. 使用限制

- 这是**工程样本**，不是全国岗位市场统计；行业、地区、学历结构受两个来源的发布对象影响，尤其高校平台偏向校招与本科，BOSS 聚合页偏向社招与蓝领/服务业。
- 单条招聘广告不等于完整职业介绍；职业方向判断还需职业介绍、从业者经历和本人核实。
- BOSS 条目的薪资、发布日期、完整职责可能缺失或被截断；`salary_text` 只作原文记录，不用于跨岗位比较。
- 企业资质、岗位是否仍在招、是否收费或存在招聘风险，均未逐条核验；不得把 `pending` 当作已核实。
- 岗位会过期、改版或下架；下次使用前应按 `source_url` 复核，超过 30 天未复核的按项目规则标“需要复核”。

## 6. 复现

```bash
python3 -I scripts/collect_job_samples_2026-11-02.py
python3 -I scripts/collect_boss_listing_samples_2026-11-02.py
python3 -I scripts/validate_job_samples_2026-11-02.py
```

第一个脚本只采高校平台；第二个脚本只读 BOSS 公开聚合页；第三个脚本合并、去重、过滤公告并生成主表、台账与索引。三个脚本都只使用 Python 标准库。

## 7. 下一步建议

1. 人工抽查至少 30 条，重点核对：职责与要求是否错位、必需/优先是否被误分、学历与届别是否原文支持；通过后把对应条目改为 `verified`，不整批改状态。
2. 为`职业规划核心流程 v0.1`第 4 节样例补 2 个方向的可读职业介绍与从业者经历，与本样本的活动策划/内容类岗位对照。
3. 鱼泡等蓝领平台如确需使用，先确认平台条款与可访问方式；不要用验证码绕过或登录账号批量抓取。
